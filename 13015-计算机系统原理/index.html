本章速记图：
  • 第一章 计算机系统概述（考点 1—13）
    • 主线：计算机如何工作 → 程序如何变成机器指令 → 如何评价性能
    • 1. 存储程序A
      • 程序 + 原始数据先送入主存
      • 启动后自动逐条取指、执行
      • 易错：不是“程序存在硬盘上”就算存储程序
    • 2. 冯·诺依曼结构S
      • 四大思想：存储程序、五大部件、指令数据同存主存、二进制
      • 五大部件：运算器、控制器、存储器、输入、输出
      • 易错：寄存器属于 CPU 内部，不单列为五大部件之一
    • 3. 模型机与 CPUS
      • 模型机：主存 + ALU + 控制器 + I/O
      • CPU = 控制部件 + 运算部件 + 各类寄存器
      • PC：下一条指令地址；IR：当前指令
      • 总线：地址线传地址 / 数据线传数据 / 控制线传命令
    • 4. 指令B
      • 指令 = 操作码（做什么）+ 地址码（操作数在哪）
      • 模型机 8 位定长指令
        • R 型：op(4) + rt(2) + rs(2)
        • M 型：op(4) + addr(4)
      • load：主存→寄存器；store：寄存器→主存
    • 5. 指令执行过程A
      • 取指 → 译码 → 算源地址/取操作数 → 执行
        • → 算目的地址/存结果 → 计算下一条指令地址
    • 6. 翻译程序S
      • 汇编程序：汇编语言 → 机器语言
      • 编译程序：高级语言 → 目标代码（常先生成汇编）
      • 解释程序：逐条翻译并执行
      • 易错：链接程序不属于三类翻译程序
    • 7. 源程序到可执行文件S
      • 预处理 → 编译 → 汇编 → 链接
        • .c → .i（文本）→ .s（文本）→ .o（二进制）→ 可执行文件
    • 8. ISA 与抽象层A
      • ISA = 软件与硬件的接口完整定义
      • 规定指令、操作、操作数类型与地址空间等
      • ISA 规定“机器能做什么”；微体系结构规定“内部如何实现”
    • 9. 系统软件与用户A
      • 系统软件：操作系统、编译器、DBMS、实用程序
      • 应用软件：办公、游戏、播放器等
      • 用户：最终用户 / 系统管理员 / 应用程序员 / 系统程序员
    • 10. API 与 ABIC
      • API：源程序级接口；兼容时可在目标平台重新编译
      • ABI：二进制级约定；兼容时编译好的程序才可能直接运行
    • 11. 性能指标S
      • 吞吐率：单位时间完成的工作量
      • 响应时间：一个任务从开始到完成的时间
      • CPU 时间 = 用户 CPU 时间 + 系统 CPU 时间
      • 主频 f = 1 / 时钟周期 T；CPI = 每条指令平均周期数
    • 12. 性能计算S
      • CPU 时间 = 总时钟周期数 / 主频
      • 总周期数 = Σ(CPIᵢ × 指令条数 Cᵢ)
      • 综合 CPI = 总周期数 / 总指令条数
      • MIPS = 指令条数 / 执行时间 / 10⁶ = 主频 / (CPI × 10⁶)
      • 解题：先算总周期数，再算时间；不要只比较主频或指令条数
    • 13. 基准程序C
      • 用一组代表性程序评估机器性能
      • 比较同一基准程序在不同机器上的运行时间
      • 易错：基准程序是一组测试程序，不是一个性能公式
【做题】先统计每类指令条数 → 乘以各自 CPI → 求总周期数 → 除以主频求 CPU 时间 → 根据题目求 MIPS 或比较性能。主频更高不一定更快；MIPS 不适合直接比较不同指令集的机器。
考点1存储程序A2024.10、教材习题▼
1.1 是什么 存储程序工作方式：必须将事先编好的程序和原始数据送入主存后才能执行程序，一旦程序被启动执行，计算机不需要操作人员干预就能自动完成逐条指令取出和执行的任务。
人话：程序和数据先搬进主存，CPU 自动逐条取指令、执行指令，中途不用人管。
1.2 三个得分要点
  • 程序和原始数据都要先送主存。
  • 启动后不需要操作人员干预（自动连续执行）。
  • 逐条指令取出并执行。
1.3 真题 【教材·第一章习题二】 什么是"存储程序"工作方式？
答案：必须将事先编好的程序和原始数据送入主存后才能执行程序；一旦程序被启动执行，计算机不需要操作人员干预，就能自动完成逐条指令的取出和执行的任务。

1.4 易错 存储程序 ≠ "程序放在硬盘上"。要点是程序和数据都进主存、CPU 能自动逐条执行。

考点4指令B2026.04▼
4.1 是什么 指令：用 0 和 1 表示的一串 0/1 序列，用来指示 CPU 完成一个特定的原子操作（不可分割）。
每条指令由操作码和地址码两部分组成：操作码指明做什么操作，地址码指明操作数在哪。
4.2 模型机 8 位定长指令字（必背）
格式位段划分功能
R型op(4位) + rt(2位) + rs(2位)R[rt] ← R[rt] op R[rs] 或 R[rt] ← R[rs]
M型op(4位) + addr(4位)R[0] ← M[addr] 或 M[addr] ← R[0]
op 编码规定：0000=传送（mov）、0001=加（add）、1110=取数（load）、1111=存数（store）。
两条必会的指令：`0001 0001` → R[0]←R[0]+R[1]；`1110 0110` → R[0]←M[0110]（6 号主存单元）。
4.3 四类基本指令与数据流向
  • load（取数，M型）：主存 → 通用寄存器。
  • store（存数，M型）：通用寄存器 → 主存。
  • add（加，R型）：通用寄存器 → 通用寄存器。
  • mov（传送，R型）：通用寄存器 → 通用寄存器。
4.4 真题 【2026.04·填空11】 指挥计算机如何操作的指令序列称为＿＿，指令操作的对象是＿＿。
答案：程序、数据
【教材·第一章习题五】 仿照模型机为 v=(x−y)×y 设计指令序列（附机器代码与执行过程）。
4.5 易错 模型机指令字只有 8 位：操作码固定占高 4 位、地址码只有 4 位（寻址范围 0000~1111）。
考点5程序和指令的执行过程A2025.04、2026.04▼
5.1 核心例子：z = x + y x、y 分别放主存 5、6 号单元（x=16、y=33），结果存 7 号单元。
机器代码汇编指令含义
1110 0110load r0, 6#R[0] ← M[6]（取 y）
0000 0100mov r1, r0R[1] ← R[0]（y 备份到 r1）
1110 0101load r0, 5#R[0] ← M[5]（取 x）
0001 0001add r0, r1R[0] ← R[0] + R[1]（x+y）

add 指令：A ← R[0]、B ← R[1]（取两个操作数）→ 加法运算得 F → R[0] ← F。
5.3 一条指令执行的六步（简答模板） 取指令 → 指令译码 → 计算源操作数地址并取操作数 → 执行操作 → 计算目的操作数地址并存结果 → 计算下一条指令地址。

10.1 必背区分

考点11计算机性能的测试S2024.10、2025.04、2026.04▼
11.1 两个基本指标
  • 吞吐率：单位时间内完成的工作量。
  • 响应时间：从任务开始到任务完成的时间。
11.2 时间构成 执行时间 = CPU 时间 + 其他时间；CPU 时间 = 用户 CPU 时间 + 系统 CPU 时间。
CPU 性能 = 用户 CPU 时间——只包含 CPU 运行用户程序代码的时间。
11.3 三个核心概念（名解常客）
  • 时钟周期：CPU 里最小的时间单位（CPU 主脉冲信号的宽度）。
  • 时钟频率（主频）：CPU 的主频 = 时钟周期的倒数 = CPU 主脉冲信号的时钟频率；如 3.5GHz 即每秒 35 亿个时钟周期。
  • CPI：执行一条指令所需的时钟周期数；对一条特定指令是定值，对程序或机器是所有指令的平均值。
11.4 真题 【2024.10·名解21】 主频（教材第一章习题）
答案：CPU 主脉冲信号的时钟频率，是 CPU 时钟周期的倒数（即 CPU 每秒的时钟周期数）。
【2025.04·名解21】 时钟周期
答案：计算机执行一条指令的过程被分成若干步骤完成，每一步都要有相应的控制信号进行控制，计算机必须能够产生同步的时钟定时信号，即 CPU 主脉冲信号，其宽度称为时钟周期。
【2026.04·简答23】 简述计算机系统基本性能指标和 CPU 的性能指标。
答案：系统级性能指标 = 吞吐率、响应时间、时钟频率等；CPU 级性能指标 = CPI、MIPS、主频等。
11.5 易错 主频与时钟周期互为倒数——写名解别只写一半。 CPU 性能只算用户 CPU 时间，不含系统 CPU 时间。

      • SF：结果最高位

      • 乘法：乘积位宽通常比单个操作数更宽；有符号/无符号解释不同

      • 对阶（小阶向大阶）→ 尾数加减 → 规格化 → 舍入 → 阶码溢出判断
      • 规格化：尾数左移 → 阶码减；右移 → 阶码加
      • 舍入后再检查阶码溢出

    • 32. 浮点数乘除运算B
      • 乘法：尾数相乘，阶码相加
      • 除法：尾数相除，阶码相减
      • 然后规格化 → 舍入 → 阶码溢出判断

考点18补码表示法与模运算S2025.04、2025.10、2026.04▼
18.1 为什么用补码（简答/单选必背） 补码实现加减法统一——用加法来实现减法运算：允许加法和减法使用相同的硬件电路，简化计算机的设计（无需单独的减法电路）。
18.2 模运算模型（钟表） 模 12 系统中：10 − 4 ≡ 10 + (12 − 4) ≡ 10 + 8 ≡ 6 (mod 12)，即 −4 ≡ 8 (mod 12)。

18.3 求补码（必背） 负数补码 = 模 − |X| （模 = 2ⁿ，n 为补码位数） [X]补 = M + X (mod M) （正负数通用公式） 简便方法（真值求补码）：
  • 正数：符号位取 0，数值部分不变。

  • 条件设置 SETcc：把条件值（0/1）设置到一个 8 位通用寄存器，如 setc %dl：CF=1 则 R[dl]=1。

  • 陷阱指令：重要作用之一是系统调用。

考点47过程调用S2024.10▼
47.1 过程调用六步（必背） 1. P 将入口参数（实参）放到 Q 能访问到的地方。
2. P 将返回地址存到特定地方，然后将控制转移到 Q。
3. Q 保存 P 的现场，并为自己的非静态局部变量分配空间。
4. 执行 Q 的过程体（函数体）。
5. Q 恢复 P 的现场，并释放局部变量所占空间。
6. Q 取出返回地址，将控制转移到 P。
47.2 栈与栈帧
  • 调用过程与被调过程各有一个栈区（栈帧）；EBP（帧指针寄存器）指向当前栈帧底部。
  • 汇编视角：call 指令把返回地址压栈并转移控制；被调过程保存现场、为局部变量分配栈帧；ret 取出返回地址回到调用点。
  • 名解备选：当前栈帧、帧指针寄存器、嵌套调用（函数内调函数）、递归调用（函数调自身）、调用者保存寄存器、被调用者保存寄存器。
47.3 真题 【2024.10·简答23】 简述在递归深度较深时，递归调用的时间开销和空间开销都会较大的原因。（教材第三章习题第 7 题原题）
答案：每个过程包含准备阶段和结束阶段，并在栈中新增一个栈帧；每增加一次过程调用，就要增加许多条包含在准备阶段和结束阶段的额外指令，并增加一个栈帧的空间。递归调用深度较深时，这些额外指令的执行时间开销和栈帧的空间开销就会很大，有些情况下甚至发生栈溢出。
47.4 易错 递归开销答题要两个点：时间（每次调用多一组准备/结束指令）+空间（每层多一个栈帧）——只答一个只拿一半分。 栈是"先进后出"访问、从高地址向低地址增长——方向别答反。

51.1 两条对齐规则（必背） 1. 成员对齐：结构体中每个成员的偏移量必须是该成员自身大小的整数倍（short→偏移为 2 的倍数；int→偏移为 4 的倍数）。

51.2 例3.11（空间优化实操） struct { char a; int b; char c; short d; } record[100]; 原布局：a@0 b@4~7 c@8 d@10~11 元素 12 字节 → 数组 1200 字节 调序（短→长）：d@0~1 c@2 a@3 b@4~7 元素 8 字节 → 数组 800 字节
  • 结论：调整成员声明顺序使占用空间最少（短→长或长→短均可），本例省 400 字节。
51.3 教材简答（8） 为什么数据最好按对齐方式存放——许多体系结构对数据访问有对齐要求；若存放不对齐，可能导致额外的内存访问、降低访问效率。

考点52x86-64 的基本特点B未单独出题▼
52.1 六条特点（必背）
  • 通用寄存器个数比 IA-32 更多。
  • 通用寄存器位数从 32 位扩展到 64 位；字长 64 位，逻辑地址 64 位。
  • long double 仍用 80 位扩展精度格式，但分配空间从 IA-32 的 12 字节增至 16 字节。
  • 过程调用时，整型入口参数在 6 个以内用通用寄存器传递（不用栈）——很多过程可不访问栈、执行时间更短。
  • 128 位的 XMM 寄存器从 8 个增加到 16 个，浮点操作基于 SSE、操作数放 XMM 寄存器。
52.2 易错 "x86-64 参数还是走栈"是错的——前 6 个整型参数走寄存器（RDI、RSI…），这是与 IA-32 的关键区别。

62.2 GCC 链接器处理多重定义同名全局符号的规则（简答必背） 1. 强符号不能多次定义，否则链接错误。
2. 一次强符号定义 + 多次弱符号/COMMON 定义 → 按强符号为准。
3. 同时出现 COMMON 和弱符号定义 → 按 COMMON 为准。
4. COMMON 符号多次定义 → 以占空间最大的一个为准。
5. 用编译选项 -fno-common → 不考虑 COMMON，相当于把 COMMON 当强符号处理。
62.3 避免同名全局符号问题的三条做法
  • 定义成 static 属性的静态变量。
  • 给全局变量赋初值,使其成为强符号。
  • 引用外部全局变量时尽量用 extern 声明。

63.1 定义与扩展名
  • 静态链接：将多个目标模块打包成静态库文件的机制；类 UNIX 中静态库扩展名为 .a。
  • 动态链接：在可执行文件装入或运行时动态装入内存并自动链接；类 UNIX 中共享库扩展名 .so，Windows 中共享库扩展名 .dll。
63.2 三点区别（简答模板）
维度静态链接动态链接
链接时机形成可执行程序之前（编译过程中）完成程序运行时（装入或执行时）动态加载

考点67指令流水线S2025.10▼
67.1 四阶段 取指令并 PC 加 1（IF）→ 译码并读寄存器（ID）→ 运算或读存储器（EX）→ 结果写回（WB）。
指令经过阶段耗时
addIF+ID+EX+WB200+60+100+50 = 410ps
loadIF+ID+EX+WB200+60+200+50 = 510ps
movIF+ID+WB200+60+50 = 310ps
storeIF+ID+WB200+60+200 = 460ps
串行合计1690ps
各阶段时间：取指 200ps、译码 60ps、ALU 100ps、访存/写存 200ps、寄存器写 50ps。
67.2 流水线总时间公式（必背） 总时间 = (M − 1 + N) × T M = 流水段数，T = 每个流水段执行时间，N = 指令条数 例：4 段流水线、每段 200ps、4 条指令 → (4−1+4)×200 = 1400ps。
67.3 设计原则（必背两条） 1. 指令流水段个数以最复杂指令所用的阶段数为准（最复杂的 load 用了 4 个阶段，M=4）。
2. 流水段执行时间以最复杂操作所用时间为准（最复杂操作访存 200ps，T=200ps）。
67.4 核心结论（易考简答）
  • 流水线中每条指令的执行时间为 4×200=800ps，比串行最长的 510ps 还长——流水线并不能缩短一条指令的执行时间。
  • 但对整个程序而言，流水线可大大增加指令执行的吞吐率（总时间由 (3+N)×200ps 给出，N 越大收益越大）。
  • 瓶颈段决定流水线的加速：只有缩短最慢段才能加快流水线。
67.5 真题 【2025.10·分析设计29】 4 段指令流水线中各功能部件操作时间：指令译码 60ps、PC 加 1 需 50ps、存储器读或写需 250ps、ALU 需 180ps、寄存器读或写需 70ps。请回答：(1) 若执行 EX 阶段所用的 ALU 操作时间缩短 20%，能否加快流水线执行速度？为什么？(2) 若 ALU 操作时间增加 20%，对流水线的性能有何影响？
答案：(1) 缩短后 ALU = 144ps < 250ps，不能加快——流水线执行速度取决于最慢的功能部件（存储器 250ps）；(2) 增加后 = 216ps < 250ps，对流水线性能没有影响。
67.6 易错 教材习题解答说流水线"一条指令的执行时间缩短了"——与课件口径矛盾，考试按课件：单条指令时间不缩短、程序吞吐率提高。 总时间公式别写成 N×T（那是理想满载稳态）；启动阶段 (M−1)×T 别漏。

      • 越靠近 CPU：通常速度快、容量小、单位成本高
      • Cache 与主存交换数据以“块”为单位
      • Cache 缺失主要由硬件处理；缺页通常由 OS 软件处理
    • 70. 程序访问局部性A
      • 时间局部性：近期访问过的数据/指令可能再次访问
      • 空间局部性：访问地址附近的数据/指令可能随后被访问
      • 例5.1 口径：行优先遍历→空间局部性好；列优先→无空间局部性
      • 数组元素只访问一次→时间局部性差；sum、循环体→时间局部性好
      • 同一程序改循环顺序：执行速率差 21.5 倍（2GHz Pentium 4）
    • 71. Cache 基本原理S
      • 命中率 p；命中时间 Tc；缺失损失 Tm
      • 平均访问时间 Ta = Tc + (1−p)×Tm
      • 做题：先确认 Tm 指“额外损失”还是“完整缺失时间”
    • 72. 直接映射S
      • 行号 = 主存块号 mod Cache 行数
      • 地址 = 标记 | 行号 | 块内地址
      • 行数 = Cache 数据容量 / 块大小
      • 易错：直接映射一个主存块只能去唯一 Cache 行
    • 73. 全相联映射S
      • 主存块可以放到任意 Cache 行
      • 地址 = 标记 | 块内地址
      • 查找时比较各行标记
      • 易错：没有行号/组号字段；查找硬件开销大
    • 74. 组相联映射S
      • 组号 = 主存块号 mod 组数
      • 组数 = Cache 行数 / 路数
      • 地址 = 标记 | 组号 | 块内地址
      • 每组有多行；在该组内部比较标记
    • 75. 三种映射比较B
      • 直接映射：硬件简单，冲突多
      • 全相联：位置灵活，硬件开销大
      • 组相联：两者折中
    • 76. 替换算法A
      • FIFO：替换最早进入者
      • LRU：替换最长时间未被使用者
      • LFU：替换访问次数较少者
      • 直接映射只有固定位置，不需要在多行中选择替换对象
    • 77. Cache 写策略S
      • 通写（Write-through）：写 Cache 同时写主存
      • 回写（Write-back）：替换脏块时才写回主存
      • 写分配：写缺失时把块调入 Cache 再写
      • 非写分配：写缺失时直接写主存，不调入 Cache
    • 78. Cache 性能计算A
      • 命中率 = 命中次数 / 总访问次数
      • 平均访问时间 = 命中时间 + 缺失概率×缺失损失
      • 地址→块号：块号 = ⌊地址 / 块大小⌋
      • 组号 = 块号 mod 组数
      • 数组元素地址 = 起始地址 + (行×列数 + 列)×元素字节数
    • 79. 主存扩展S
      • 芯片数 = (目标容量 / 芯片容量) × (目标字长 / 芯片字长)
      • 字扩展：增加字数/地址空间
      • 位扩展：增加每个字的位数
      • 片内地址位数 = log₂(芯片字数)
      • 更高地址位用于片选/模块选择
      • 先画地址范围，再确定片内地址线、片选逻辑和芯片数量
    • 80. 磁盘存储A
      • 平均存取时间 = 平均寻道时间 + 平均旋转等待 + 传输时间
      • 平均旋转等待通常按半圈计算
      • 旋转等待：转速 r rpm 时，平均等待 = 30/r 秒
      • 易错：统一秒、毫秒、微秒；传输时间取决于数据量与传输率
    • 81. 虚拟存储S
      • 虚拟地址 = 虚页号 | 页内地址
      • 物理地址 = 实页号 | 页内地址
      • 页大小相同 → 页内地址位数不变，只转换页号
      • 页表大小 = 虚页数 × 每个页表项大小
      • TLB：页表项的高速缓存
      • 缺页：页不在主存，需由 OS 处理并调页
      • 权限保护
        • 越权：访问操作与权限不符
        • 越界：访问未分配/无效区域
        • 越级：用户态访问内核区
      • 易错
        • 页内偏移位数不变
        • 缺页与 TLB 命中不能同时成立于同一缺失页表项的常规情形
        • 逻辑地址转换涉及硬件地址转换与 OS 缺页处理的协作

    • 2. 求块内地址位数：log₂(块大小，单位 B)

  • 易失性存储器：电源关闭后数据会丢失的存储设备（主存、cache）。

考点71cache 的基本工作原理S2025.04、2026.04▼
71.1 访存过程与有效位
  • 整个访存过程：判断信息是否在 cache → 在：直接从 cache 取信息；不在：从主存取一个主存块装入 cache（对应行已满则先替换）。
  • cache 中的内容是主存中部分内容的副本；每个 cache 行有一个有效位：淘汰行中主存块时清 0，装入新主存块时置 1。
71.2 命中/缺失与两个时间量（必背）
  • 访问单元所在块在 cache 中 → cache 命中；命中概率 = 命中率 p = 命中次数/访问总次数；命中时访问时间 = cache 访问时间 Tc（命中时间）。
  • 不在 cache 中 → 缺失（不命中）；缺失率 = 不命中次数/访问总次数；缺失时需从主存读主存块送 cache、并同时将所需信息送 CPU——所用时间为 Tm（主存访问时间）+ Tc；通常把 Tm 称为缺失损失。
71.3 平均访问时间公式（必背） Ta = p × Tc + (1 − p) × (Tm + Tc) = Tc + (1 − p) × Tm p = 命中率，Tc = 命中时间，Tm = 缺失损失（主存访问时间） 71.4 例5.2（模板：先数次数再代公式）
  • 时钟周期 2ns；3000 条指令每条执行一次、其中 4 条取指缺失；执行中 1000 次数据访问、其中 6 次缺失。
  • 访问总次数 = 取指 3000 + 数据 1000 = 4000；缺失数 = 4 + 6 = 10。
  • ① 命中率 = (4000−10)/4000 = 99.75%。
  • ② 题干给出 Tc = 1、Tm = 10（单位：时钟周期）→ Ta = 1 + (1−99.75%)×10 = 1.025 个时钟周期 = 1.025×2 = 2.05ns。
71.5 名解候选（教材第五章习题第1题）
  • 主存块：主存中可以被作为一个单元整体传输到 cache 中的一组数据。
  • cache 行（槽）：cache 中用于存储数据的基本单元。
  • 命中率：cache 访问成功的次数与总访问次数的比例。
  • 命中时间：cache 命中时，从发出数据请求到数据实际可用所需的时间。
  • 缺失损失：cache 未命中时，从慢速存储器（主存）获取数据所需的额外时间和开销。

考点72直接映射S2024.04▼
72.1 映射规则（必背） 每个主存块映射到 cache 的固定行中，也叫模映射：
cache 行号 = 主存块号 mod cache 行数
  • 例：cache 有 16 行，100 mod 16 = 4 → 主存第 100 块映射到 cache 第 4 行。
72.2 地址划分四步法（大题模板） 以例5.3 为例（主存 256KB、块 64B、cache 数据区 1KB）：
1. 主存地址位数 = log₂(主存空间) = log₂(256×1024) = 18 位；
2. 块内地址位数 = log₂(块大小) = log₂64 = 6 位；
3. cache 行号位数 = log₂(cache 数据区 ÷ 块大小) = log₂(1KB/64B = 16 行) = 4 位；
4. 标记位数 = ①−②−③ = 8 位。
地址格式 = 标记(8) | cache 行号(4) | 块内地址(6)；前 12 位（标记+行号）= 主存块号；标记即"块群"号：主存 4096 块分成 256 个块群（每群 16 块），第 i 块群的第 x 块固定映射到 cache 第 x 行。
72.3 访问过程（例5.3 标准写法）
  • 0240CH = 0000 0010 0100 0000 1100 → 按 18 位（8|4|6）截取：00001001 | 0000 | 001100；
  • 主存块号 = 前 12 位 = 000010010000 = 144（第 9 块群第 0 块）→ cache 行号 = 0；
  • cache 当前为空（各行有效位为 0）：不管第 0 行标记是否等于 00001001 都不命中 → 将第 144 块复制到 cache 第 0 行，置有效位 1、置标记 00001001。
助记：cache 空不命中 → 读数 → 装 cache → 置 1 置标记。 72.4 真题 【2024.04·分析设计30】 假定 cache 采用直接映射方式，主存块大小为 64B，按字节编址；cache 数据区大小为 2KB，主存空间大小为 256KB。试回答：(1) 主存地址如何划分？(2) 假定 cache 当前为空，说明 CPU 对主存单元 0240CH 的访问过程。（教材例 5.3 变型：数据区 1KB→2KB）
答案：
  • 地址划分：18 位总；6 位块内；2KB/64B = 32 行 → 5 位行号；标记 = 18−6−5 = 7 位；
  • 0240CH → 7|5|6 = 0000100 | 10000 | 001100：块号 144、行号（144 mod 32）= 16、标记 0000100；
  • 访问：cache 空 → 不命中 → 将 0240CH 所在块装入 cache 第 16 行，置有效位 1、标记 0000100。
72.5 易错 行数一变，行号位数就变：1KB/64B=16 行→4 位；2KB/64B=32 行→5 位——标记位数随之反向变化（18 位总数不变）。 "标记 = 块群号"，别把标记写成块号（块号 = 标记+行号，共 12 位）。
考点73全相联映射S2024.10▼
73.1 映射规则与地址格式
  • 每个主存块可映射到 cache 的任意行中——地址没有行号/组号字段。
  • 地址划分三步：① 主存地址位数；② 块内地址位数；③ 标记位数 = ①−②（标记即主存块号）。
73.2 例5.4 地址划分 256KB、块 64B、cache 数据区 1KB（16 行）：18 位总；6 位块内；标记 = 12 位 = 主存块号（共 4096 块）。
地址格式 = 标记(12) | 块内地址(6)。
73.3 访问过程（标准写法）
  • 0240CH → 按 12|6 截取：000010010000 | 001100 → 标记 = 000010010000 = 144（第 144 块）。
  • 将高 12 位标记与每个 cache 行的标记比较：
  • 有一个相等且有效位为 1 → 命中，按块内地址 001100 从该行取出信息；
  • 都不相等 → 不命中：将主存第 144 块读出，装入任意一个空闲行，置有效位 1、置标记 000010010000。
助记：比较 → 相等且有效位 1 才命中 → 否则读数、装 cache、置 1 置标记。 73.4 真题 【2024.10·分析设计30】 假定 cache 采用全相联方式，主存块大小为 64B，按字节编址；cache 数据区大小为 1KB，主存空间大小为 256KB。试回答：(1) 主存地址如何划分？(2) 说明 CPU 对主存单元 0240CH 的访问过程。（教材例 5.4 原题）
答案：
  • 地址划分 = 12 位标记 + 6 位块内（共 18 位）；
  • 0240CH 的高 12 位标记 = 144 号主存块；访问 = 与所有行标记逐一比较 → 命中取数 / 缺失装入任意空闲行。
73.5 易错 全相联地址只有"标记+块内"两段——画出"行号/组号"必错。 "比较所有 cache 行"是全相联的过程标志；直接映射只比 1 行、组相联只比对应组内各行。

74.1 映射规则（必背） 每个主存块映射到 cache 的固定组的任意行中：
cache 组号 = 主存块号 mod cache 组数
  • 例：1KB cache = 2³ 组 × 2 行/组 × 64B/行；主存第 100 块 → 100 mod 2³ = 4 → 第 4 组的任意行中。
74.2 例5.5 地址划分（2 路组相联） 256KB、块 64B、cache 数据区 1KB：18 位总；6 位块内；1KB/64B = 16 行 ÷ 2 路 = 8 组 → 3 位组号；标记 = 18−6−3 = 9 位。

  • 按组号找到 cache 第 0 组：将标记与组内各行的标记比较——有一个相等且有效位为 1 → 命中取数；都不相等 → 不命中：将第 144 块装入该组任意空行，置有效位 1、置标记 000010010。
助记：先定位到组 → 再在组内比较（2 路就比 2 行）。 74.4 总容量计算模板（必背） 每行总位数 = 数据部分位数（块大小×8） + 标记位数 + 1 位有效位 + 修改位（回写才有） + 使用位（LRU 位数 = log₂路数）

  • FIFO 算法：最早进入缓存的数据项最先被移出——"总是选择最早装入 cache 的主存块被替换"。
  • LRU 算法：最近最少使用的数据项未来被访问的可能性最小 → 替换最久未使用的。
  • LRU 位：跟踪缓存中数据项使用情况、以便实现 LRU 算法的位。

考点77cache 的写策略S2024.04▼
77.1 为什么有写策略问题
  • cache 中的内容是主存块的副本：当 CPU 更新 cache 中内容时，需要考虑何时更新主存中的相应内容、使两者保持一致——这就是写策略问题。
  • 教材简答口径：若不对 cache 和主存要修改的内容加以控制，两者内容会变得不一致；需采用适当写策略决定何时、如何将 cache 中数据写回主存。
77.2 两种写策略（必背） 通写法（Write Through）：
  • 命中：将数据同时写入主存和缓存（保证一致性）。
  • 不命中：先写入主存，然后两种处理：
  • 写分配法：分配一个 cache 行并装入更新后的主存块（充分利用空间局部性）；
  • 非写分配法：不将主存块装入 cache（没有充分利用空间局部性）。
回写法（Write Back）：
  • 命中：只写缓存，不立即写主存；当缓存行被替换时才将数据写回主存。
  • 写缺失（不命中）：分配一个 cache 行、装入主存块，然后更新该行内容。
  • 需要修改位（脏位）记录"是否被修改过"；通常与写分配法组合使用。
77.3 真题 【2024.04·填空19】 cache 的写策略有＿＿法和＿＿法。
答案：通写、回写
（对总容量计算的影响：通写无修改位、回写有修改位——见考点74。）
77.4 易错 通写 = 命中时同时写主存+cache；回写 = 命中时只写 cache、替换时才写回——两句互为镜像，别写反。 "回写法通常与写分配法组合使用"是教材原文考点。

考点79主存芯片与容量扩展（自建）S2024.04、2024.10▼
79.1 主存的基本概念（名解候选）
  • 记忆单元（Cell，存储元/位元）：具有两种稳态、能表示 0/1 的物理器件，是存储器的核心部分；大量记忆单元构成存储阵列（Bank，存储体/存储矩阵）。
  • 编址方式：对各存储单元进行编号的方式（按字节编址/按字编址）；编址单位：具有相同地址的那些位元构成的单位（现在通用计算机大多按字节编址）。
  • 存储周期：存储器进行连续两次独立操作（读或写）之间所需的最小时间间隔。
  • 地址线位数决定最大可寻址范围（如 36 位 → 0~2³⁶−1）；CPU 通过 MAR/MDR 与主存交换信息，现代 CPU 先与主存控制器（DRAM 控制器）交互。
79.2 芯片与连接（必背要点）
  • 主存常用 SDRAM 芯片（DDR3 等）：与总线时钟同步、支持突发传输；DDR 在时钟上升沿与下降沿各传一次数据。
  • DRAM 芯片内地址分行地址 i 和列地址 j（RAS/CAS 分时送入），同时读写行列交叉点的 8 位数据（8 个位平面）。
  • 图5.7：8 片 16M×8 位 DRAM 构成 128MB 内存条，行/列地址各 12 位；8 片同时读出 64 位。
79.3 扩展三型（必背）
  • 位扩展：位数不够——多片并联，位数相加（8 片 4K×1 位 → 4K×8 位）。
  • 字扩展：容量不够——高位地址用于片选，容量相加（4 片 16K×8 位 → 64K×8 位）。
  • 字位同时扩展：容量和位数都不够（16K×4 位 → 64K×8 位 = 字扩展 4 倍 × 位扩展 2 倍）。
芯片数 = (目标容量 ÷ 芯片容量) × (目标字长 ÷ 芯片字长) 79.4 真题计算 【2024.04·计算28】（教材第五章习题 3）某计算机主存最大寻址空间为 4GB，按字节编址；用 64M×8 位（8 个位平面）的 DRAM 芯片组成容量为 512MB、传输宽度 64 位的内存条。问：(1) 每个内存条需要多少片 DRAM 芯片？(2) 构建容量为 2GB 的主存需要几个内存条？(3) 主存地址共多少位？哪几位用于芯片内地址、哪几位用于选择芯片？
答案：
  • 每个内存条芯片数 = 512MB ÷ (64M×8 位 = 64MB) = 8 片；
  • 2GB 主存 = 2GB ÷ 512MB = 4 个内存条；
  • 地址划分：2³² = 4GB → 主存地址共 32 位——A25~A0 为芯片内地址（每片 64MB = 2²⁶B）；A26~A28 用于选择芯片（每条 8 片 = 2³）；A29~A31 用于选择内存条（至多 8 条；2GB 时用 A29~A30 选 4 条）。
【2024.10·计算28】（教材第五章习题 4）某机按字节编址，已配有 0000H~7FFFH 的 ROM 区；再用 16K×4 位 RAM 芯片形成 32K×8 位的存储区，CPU 地址为 A15~A0。问：(1) RAM 区的地址范围是什么？共需多少个 RAM 芯片？哪一位地址线用来区分 ROM 和 RAM 区？(2) 若 CPU 地址线改为 24 根、000000H~007FFFH 为 ROM 区、剩下所有地址空间都用 16K×4 位 RAM 芯片配置，需要多少个 RAM 芯片？
答案：
  • RAM 区地址范围 = 8000H~FFFFH；芯片数 = (32K/16K)×(8/4) = 4 片；A15 用来区分 ROM 区（低 32KB）与 RAM 区（高 32KB）；
  • 地址线改为 24 根时：其余空间 = 2²⁴ − 2¹⁵ 字节，每片（16K×4 位）= 8KB → 芯片数 = (2²⁴−2¹⁵) ÷ 8KB = 1022×2 = 2044 片。
79.5 地址对齐（教材简答）
  • 一次同时读出 64 位（8 个单元）：int 数据不对齐（如落在第 6~9 单元）需要访问两次存储器；对齐（起始地址是 4 的倍数）则一次访问即可。
  • 教材简答：为什么采用地址对齐方式能减少访问 DRAM 中数据的时间——DRAM 访问以块为单位，数据跨块就需多次访问；对齐使数据按块大小组织、一次取完。
79.6 易错 地址字段的完整分解：32 位 = A31~A29（选条）+ A28~A26（选片）+ A25~A0（片内）＝3+3+26；"64M×8 位"芯片容量 = 64MB。 2024.10(2)：总空间先扣 ROM 的 32KB 再除"每片 8KB"（16K×4 位 = 8KB）——按"1022×2 = 2044"两步推更稳。
考点80磁盘存储器（自建）A2024.04、2025.10▼
80.1 结构与术语
  • 磁盘存储器 = 磁记录介质 + 磁盘驱动器 + 磁盘控制器。
  • 磁头与盘片相对运动形成磁道（磁头号=盘面号）；多盘片相同磁道形成柱面（磁道号=柱面号）；磁道分扇区，以扇区为单位读/写；写完一个柱面再移到下一个；磁道从外向里编号（最外为磁道 0）。
  • 温盘定长记录格式：头空 17B、ID 域、间隙 2、数据域 515B（真正数据区 512B）、尾空 20B。

2. 旋转等待：指定扇区旋转到磁头下方（扇区符合信号）；

80.3 性能指标（必背四条）
  • 记录密度（道密度、位密度）；存储容量（格式化容量 < 未格式化容量；按每扇区 512B 计算实际容量）；数据传输率（内部传输率/外部传输率）；平均存取时间。
  • 平均存取时间 = 平均寻道时间 + 平均旋转等待时间 + 数据传输时间：
  • 平均寻道 5~10ms；平均等待 = 磁盘转一周时间的一半（6000 r/min → 约 5ms）；
  • 数据传输时间极短（约 0.01ms/扇区）→ 平均存取时间通常近似 = 寻道 + 等待；即磁头定位到目标扇区后，数据本身的传输几乎没有延迟。
80.4 时间计算模板（教材第五章习题5） 4KB 数据块"读出—处理—写回"；7200 r/min；平均寻道 10ms；传输率 40MB/s；控制器开销 2ms；处理 20000 周期@500MHz；读写与处理不重叠：

  • 传输时间 = 4KB ÷ 40MB/s = 0.1ms；
  • 一次磁盘操作 = 10 + 4.17 + 0.1 + 2 = 16.27ms；
  • 处理时间 = 20000 ÷ 500MHz = 0.04ms；
  • 总时间 = 16.27 + 0.04 + 16.27 = 32.58ms → 每秒约 1000/32.58 ≈ 30.7 次。

考点81虚拟存储器（自建）S2024.10、2025.04、2025.10、2026.04▼
81.1 为什么需要（基本概念）
  • 解决两个问题：①早期主存容量受限——让编程不受物理内存大小制约；②让多个程序有效而安全地共享主存。
  • 机制：CPU 通过存储管理部件（MMU）把指令中的逻辑地址（虚拟地址 VA）转换为主存的物理地址（PA）；转换过程中 MMU 还检查：信息是否在主存（不在→通知操作系统从外存调入）、地址是否越界或访问越权（→异常处理）。
  • 由硬件与操作系统共同协作实现（进程、存储管理、缺页处理）。
81.2 虚拟地址空间（2026.04 填空19）
  • 分两大部分：操作系统内核区（内核空间） + 用户存储空间（用户空间）。
  • 用户空间五个区域：用户栈（从高地址向低增长）、共享库、堆（从低向高增长）、可读/写数据区、只读数据和代码区。
  • 三个好处：①每个进程有一致的虚拟地址空间（简化存储管理、链接与加载）；②把主存当作硬盘的缓存（仅存活动部分，有限主存高效利用）；③虚拟空间私有独立 → 保护进程互不破坏。
  • （可执行文件的存储器映像与区域划分详见第四章考点56、64。）

81.4 页表与页表项（必背）
  • 页表：描述虚拟页与主存页框（或外存位置）映射关系的数据结构；每个虚页一个页表项。
  • 页表项内容：存放位置（实页号或外存地址）、装入位（有效位/存在位）、修改位（脏位）、使用位（替换控制位）、访问权限位、禁止缓存位。
  • 三态判读：装入位 = 1 → 缓存页（存放位置 = 实页号）；装入位 = 0 且存放位置为 null → 未分配页；装入位 = 0 且有外存地址 → 未缓存页。
  • 缺页处理：按存放位置从外存读页 → 找空闲页框（无空闲则替换；回写策略下按修改位决定被淘汰页是否写回外存）→ 更新页表 → 回到发生缺页的那条指令重新执行。
  • 页表属进程控制信息、位于内核空间；页表在主存的首地址记录在页表基址寄存器中；页表过大 → 多级页表/倒置页表等方案。
81.5 地址转换（做题格式）
  • 虚拟地址 = 虚页号 | 页内地址；物理地址 = 实页号 | 页内地址（页大小相同 → 两者页内地址位数相同）。
  • 转换：按页表基址寄存器找到页表 → 以虚页号为索引取页表项 → 装入位为 1：实页号拼接页内地址 = 物理地址；装入位为 0：缺页。
2025.10 分析设计30（完整解题）：逻辑地址 40 位、物理地址 32 位、页大小 16KB；页表项含有效位、修改位各 1 位，使用位、存取方式位各 2 位。
1. 页内地址 = log₂16K = 14 位；逻辑地址 = 26 位虚页号 + 14 位页内；物理地址 = (32−14) 18 位实页号 + 14 位页内；
2. 页表项数 = 2²⁶；每个页表项 = 1+1+2+2+18 = 24 位；页表大小 = 2²⁶ × 24 位 = 2²⁶ × 3B = 192MB。
81.6 TLB（快表）与三种缺失
  • TLB（快表）：把最活跃的若干页表项复制到高速缓存中；主存中的页表称慢表。查 TLB 命中 → 直接转换；缺失 → 访问慢表（并装入新 TLB 表项，TLB 满时替换，常用随机替换）。
  • TLB 大多采用全相联或组相联（关联度高）；TLB 表项 = 页表项 + TLB 标记；存数指令不会将数据写入 TLB → TLB 无须考虑写策略。
  • 三种缺失：TLB 缺失、cache 缺失、缺页（page miss）。
  • 组合规律（教材表5.1）：缺页却 TLB/cache 命中 → 不可能（页不在主存，TLB 中不会有该页表项、cache 中更不会有该信息）；TLB 命中则页一定命中；最好情况全命中（不需访主存）；TLB 命中+页命中+cache 缺失需访主存一次（取块）；TLB 缺失+页命中+cache 命中也是访主存一次（查慢表）；TLB 缺失+页命中+cache 缺失为两次（查慢表＋取块）；三种全缺失 → 缺页异常、需访外存。
  • 处理者：cache 缺失 → 硬件；缺页 → 软件（操作系统缺页异常处理程序）；TLB 缺失 → 硬件或软件（依 ISA 设计）。
81.7 存储保护（名解密集区）
  • 为支持存储保护，ISA/硬件需具备三个基本功能：①部分 CPU 状态只能由内核访问（如页表基址寄存器、TLB 内容，用特权指令访问）；②支持至少两种特权模式（内核态/管态 与 用户态/目态）；③模式切换机制（系统调用/自陷指令进入高特权模式、异常返回指令退回）。
  • 访问权限保护：检查访问越权——实际访问操作与访问权限不符 → 存储保护错（在页表/段表中设访问权限位）。
  • 存储区域保护：检查地址越界——访问了不该访问的区域（如"空洞"区域、超出最大段长）。
  • Linux 页故障判断链：VA 不属于任何区域 → 段故障；操作与区域权限不符 → 访问越权；用户态访问内核区 → 访问越级——均导致终止进程；否则为正常缺页 → 调入主存。
  • 名解候选：物理地址/虚拟地址（逻辑地址）、虚拟页号/物理页号、页框（页帧）、请求分页、页表、页表基址寄存器、快表（TLB）、页故障、有效位（装入位）、修改位（脏位）、未缓存页、未分配页、存储保护、特权指令、特权模式、用户态、内核态、访问权限、地址越界、访问越权（教材第五章习题第1题）。

      • 单次中断开销 T = 处理周期数 / CPU 主频
      • 传输期间 CPU 占用率 = T / t
      • 平均占用率 = (T/t) × 设备实际工作时间占比
      • 查询方式：CPU 可能持续忙等待
      • 中断方式：每次服务有开销，频率过高会拖垮 CPU
      • DMA：CPU 主要参与初始化和完成处理，适合成块高速传输
【易错】bit 与 Byte 别混（8 bit = 1 B）；DDR 双边沿已反映在 MT/s 中，不要重复乘 2；QPI 按有效数据位数并计算双向；PCIe 按代际考虑编码效率再换算字节；中断占用率先统一单位，最后乘设备实际工作时间占比。

考点83系统调用的执行过程（以 write 为例）S2024.04、教材习题▼
83.1 write 的 5 步执行过程（必背） 必背链条：printf → write → 陷阱指令 → system_call → sys_write → 返回陷阱指令的下一条指令。 ① 用户程序调用库函数 printf ② printf 内部经一系列函数调用，最终调用 write ③ write 的指令序列中必有陷阱指令（IA-32：int $0x80 / sysenter）→ 陷入内核态 ④ system_call 按 EAX 中的系统调用号，跳转到服务例程 sys_write 执行 ⑤ system_call 结束返回用户态，从陷阱指令后面的一条指令继续执行
  • 系统调用封装函数 = 若干条传送指令（把 I/O 参数和系统调用号送寄存器）+ 一条陷阱指令。
  • Linux 惯例：系统调用号放 EAX；system_call 是统一入口。
83.2 封装函数的机器级代码结构
名词是什么例子
系统调用处理程序内核中处理系统调用请求的统一入口，按调用号分派system_call
系统调用服务例程被 system_call 调用、实现具体功能的内核函数sys_write
  • 系统级 I/O 函数 = 与 I/O 操作相关的系统调用封装函数：creat / open / read / write / lseek / stat / fstat / close。
83.3 为什么系统调用开销大（简答模板）
  • 得分点①：系统级 I/O 函数的功能由内核中的系统调用服务例程实现——用户程序每调用一次系统级 I/O 函数，就是进行一次系统调用。
  • 得分点②：每次系统调用都有两次上下文切换——先从用户态切到内核态，处理完再从内核态返回用户态。
  • 加分细节：IA-32 中系统调用属陷阱类异常——异常响应要查 IDT、做特权级检查、从用户栈切到内核栈、保存用户栈顶指针/标志寄存器/断点，再把处理程序首址送 CS:EIP。
  • 结论：能不用就不用、能少调就少调 → C 标准库用用户空间流缓冲区减少系统调用次数（见考点84.3）。
83.4 用户态/内核态判读
代码执行位置说明
C 标准 I/O 库函数：printf、scanf、fopen…用户态库函数本身在用户空间
系统调用封装函数：open、read、write…用户态封装代码 = 传送指令 + 陷阱指令
系统调用服务例程：sys_write…内核态陷阱指令之后，真正完成 I/O
  • 保险写法：封装函数在用户态执行；陷阱指令之后由内核执行服务例程（内核态），I/O 功能在内核实现。

86.1 例6.2 完整解法
  • 题：test.txt 内容为 4 个 ASCII 字符 "test"；程序两次 open 该文件（fd1、fd2），各 read 1 字节到 c，输出什么？
  • 解：前 3 个文件描述符 0、1、2 已分配给自动打开的标准设备文件 stdin、stdout、stderr，open 从 3 开始分配 → fd1=3、fd2=4；
  • 每次打开文件时 VFS 通过路径解析找到该文件的 inode，分配一个系统文件表表项并初始化：填入 inode 指针、打开模式，当前读/写位置设为 0；
  • fd1、fd2 对应两个独立的系统文件表表项，读写位置各自为 0，都指向 "test" 的字符 't' → 两次 read 读到的都是 't'。
  • 输出：`fd1=3,fd2=4,c=t`。
86.2 文件的内核数据结构（大纲"识记"）
结构内容归属
inode 表文件静态元数据：大小、所有者、权限、类型、数据寻址信息所有进程共享
系统打开文件表打开文件的动态信息：inode 指针、当前读/写位置、打开模式、引用计数全系统共享
打开文件描述符表每进程一张，索引就是 fd，表项指针指向系统打开文件表进程私有
VFS 超级块文件系统通用元数据（类型、版本等）按文件系统
目录项文件名 + 对应 inode 号目录文件内
  • 查文件链条：fd →（打开文件描述符表）→ 系统文件表项 → inode 指针 → inode 表项 → 数据寻址 → 读/写。
  • 虚拟文件系统 VFS：在逻辑文件系统层（FAT/NTFS/Ext4）之上增加的一层抽象，用超级块、目录项、inode 等内存数据结构，为上层提供统一文件操作接口。
  • 路径名：绝对路径名（以 "/" 开头，从根目录查）vs 相对路径名（从当前工作目录查）。
  • 关闭文件 close：释放本进程 fd 表项，系统文件表项引用计数减 1，减到 0 才真正释放。
  • 设备文件：主设备号确定设备类型（指定设备驱动程序），次设备号指定具体设备；设备名与文件名形式无差别（统一抽象）。
  • 名解候选：虚拟文件系统（VFS）、索引节点（inode）、inode 表、系统打开文件表、打开文件描述符表、目录项、目录文件、绝对/相对路径名。
86.3 缓存层与通用块设备 I/O 层
  • 缓存层（磁盘高速缓存）：内核主存区中的高速缓存 RAM，缓存最近访问的文件数据。
  • 访问流程：VFS 先查缓存 → 命中直接访问；不命中转逻辑文件系统 → 通用块设备层。
  • 通常采用回写策略：数据修改后先留在缓存，之后再真正写入设备。
  • 例：读 80B 数据 → 可能把包含它的整个 4KB 磁盘逻辑块读入缓存。
  • read/write 一次读写操作，在用户空间—内核空间—外存之间有两次复制传送。
两种"缓冲"别混：
用户空间流缓冲区内核磁盘高速缓存
由 FILE 等用户空间结构管理位于内核管理的主存区域
主要减少系统调用次数主要减少实际设备访问、缓存文件数据
  • 通用块设备 I/O 层：为磁盘、SSD、光盘等块设备提供统一抽象与统一逻辑块大小。
  • 提供 I/O 请求调度：合并相邻请求、重排序，降低寻道与旋转等待时间。
  • 名解候选：磁盘高速缓存、高速缓存 RAM、流缓冲区（base 起始位置、ptr 下一读写位置、cnt 剩余字节数）。

考点87设备驱动程序与三种 I/O 控制方式S2024.04、2024.10、2025.10、2026.04、教材习题▼
87.1 设备驱动程序 = 与设备相关的 I/O 软件
  • 每个设备驱动程序只处理一种外设或一类紧密相关的外设。
  • CPU 通过 I/O 指令访问设备控制器中的 I/O 端口（Linux 提供 readb/writeb 等抽象）。
  • 驱动的实现方式取决于 I/O 控制方式，主要有三种：程序直接控制、中断控制、DMA 控制（填空高频）。
  • 初始化时向操作系统注册中断服务程序，把中断号作为参数绑定（中断号制度见考点91、93）。
  • 名解候选：设备驱动程序。
87.2 程序直接控制 I/O 方式（查询/轮询） 必背（真题答案口径）：直接通过查询程序来控制主机和外设的数据交换。 读打印机状态端口 → 未就绪则反复查询 → 就绪后把内核缓冲区一个字符送数据端口 → 向控制端口发"启动打印"命令 → 循环直到全部字符打印完
  • 优点：简单、易控制、控制电路简单。
  • 缺点：CPU 忙等待——外设未就绪时反复查询，外设比 CPU 慢很多时浪费大量处理器时间。
  • 驱动与外设 I/O 完全串行；用户进程在这场 I/O 中不被阻塞。
  • 适用：简单的、数据传输要求不高的场景。
87.3 中断控制 I/O 方式（简答模板） 必背链条（漏"第一个数据/后续数据"是典型丢分点）：启动第一个数据 → 阻塞进程 → 并行 → 中断 → 服务程序启动后续数据。 ① 启动外设，先做第一个数据的 I/O 操作 ② 阻塞请求 I/O 的用户进程，调度其他进程到 CPU 上执行 ③ 外设在设备控制器控制下工作，CPU 与外设并行 ④ 外设完成 I/O，向 CPU 发中断请求 ⑤ CPU 响应 → 调出中断服务程序：启动后续数据的 I/O 操作 ⑥ 全部数据完成后，解除用户进程阻塞，放入就绪队列
  • 服务程序三步（打印机例）：① 通知控制器"中断已收到"、清除中断请求 → ② 判断是否全部完成（未完成：送下一个字符、启动打印、更新计数；完成：解除阻塞、入就绪队列）→ ③ 返回被打断的流程。
  • 进程状态：等待 I/O 完成的进程处于阻塞态；解除阻塞后进就绪队列（不保证立刻运行）。
  • 适用：对响应速度要求较高、设备速度不是特别快的场景。
87.4 DMA 控制 I/O 方式 必背：用 DMA 控制器硬件直接控制外设与主存交换数据，数据不经过 CPU。
  • DMA 控制器寄存器：主存地址寄存器、设备地址寄存器、字计数器、控制寄存器。
  • 传送前先做 DMA 初始化：写入数据个数、设备地址、主存首地址、传送方向。
DMA 初始化 → 发"启动 DMA 传送"命令 → CPU 阻塞用户进程、转去执行其他进程 → DMA 控制器控制外设与主存交换数据（每传一个数据：字计数器−1、更新主存地址） → 字计数器为 0 → 向 CPU 发"DMA 结束"中断请求 → 中断服务程序解除用户进程阻塞、放入就绪队列 → 返回
  • 适用：高速 I/O 设备的大规模数据传输（硬盘存取、图像处理）。
  • 补充口径：DMA 不执行指令搬数据，但要占总线/存储器周期（周期挪用），与 CPU 访存争带宽（见考点94.7）；cache 命中率高时大部分带宽可让给 DMA。

考点90I/O 端口及其编址S2025.04、教材习题▼
90.1 统一编址（存储器映射）方式
  • 做法：I/O 端口与主存共享同一地址空间（主存地址空间划出一部分给端口），按地址范围区分访问的是端口还是主存单元。
  • 无须专门的 I/O 指令：用一般访存指令即可访问端口，编程灵活性大增；保护机制可由虚拟存储管理机制实现。
  • 缺点：端口占用地址空间 → 可供主存使用的地址范围减少。
  • 采用者：大多数 RISC 架构（RISC-V、MIPS 用 Load/Store 指令读写 I/O 端口）。
  • MIPS32 例：I/O 端口分配在 kseg1 区域（非映射、非缓存，保证 I/O 访问一致性；上电时 MMU/cache 未工作也能访问；最高三位清零即得物理地址）。
  • 2025.04 填空20：统一编址下 I/O 访问和主存访问共用同一组指令，故其保护机制可由虚拟存储管理机制实现。
90.2 独立编址方式
  • 做法：所有 I/O 端口单独编号，形成与主存地址空间独立的 I/O 地址空间。
  • 无法从地址码区分访问对象 → 指令系统必须有专门的 I/O 指令（地址码给出端口号）；执行 I/O 指令产生 I/O 读/写总线事务。
  • 优点：端口数远少于主存单元 → 地址译码逻辑较简单；专用 I/O 指令使程序结构清晰、可读性和可维护性好。
  • 缺点：I/O 指令往往只提供简单传输操作，编程灵活性差。
  • x86 例：I/O 地址空间共 65536 个 8 位端口（两个连续 8 位端口可组成 16 位端口）；专用指令 in、ins、out、outs；把 AL 中的字符送到打印机数据缓冲寄存器（端口号 378H）。
  • 名解候选：I/O 端口、数据端口、状态端口、控制端口、I/O 地址空间、存储器映射 I/O、I/O 指令、统一编址方式、独立编址方式。
90.3 端口术语
  • 设备控制器中的数据缓冲寄存器简称数据端口；状态/控制寄存器简称状态/控制端口；所有 I/O 端口编号组成的空间称为 I/O 地址空间。

答案：指令、虚拟存储

考点91中断系统S2025.10、教材习题▼
91.1 基本功能（课件 4 项 + 教材第 5 项） 1. 及时记录各种中断请求——通常用中断请求寄存器记录。
2. 自动响应中断请求——CPU 处于"开中断"状态时，每执行完一条指令自动检测中断请求引脚，有请求即响应。
3. 自动判优——多个请求同时到时，自动选择并响应优先级最高者。
4. 保护断点和现场——使被打断的程序能正确恢复执行。
5. 中断屏蔽——通过屏蔽实现多重中断的嵌套执行（教材补充第 5 项）。
断点 vs 现场（别互换）：
名词含义由谁保存
断点被打断程序将要执行的下一条指令的地址CPU（中断响应时）
现场被打断程序在断点处各通用寄存器的内容中断服务程序
  • 中断屏蔽字：每一位对应一个中断源，1=允许中断、0=不允许（屏蔽）（教材口径；个别硬件位定义相反，答题以题目约定为准）。
  • 软件可用指令修改屏蔽字 → 动态改变中断处理的先后次序；作用是"暂停对某些中断的响应"（课件填空口径）。
  • 屏蔽字寄存器是中断控制器中的一个 I/O 端口，由 CPU 用 I/O 指令设置。
  • 开/关中断：中断响应时由硬件关中断（保护断点、现场期间不被打断）；恢复现场后开中断（中断返回指令自动恢复中断使能位）。

91.3 可编程中断控制器（PIC）与中断号
  • 中断系统功能一般通过可编程中断控制器 PIC 实现：每个设备控制器一条 IRQ 线连到 PIC。
  • PIC 把有效请求记录在中断请求寄存器对应位，对所有未屏蔽请求按优先级排队，通过 INTR 信号向 CPU 发中断请求。
  • 判优电路选出优先级最高的中断源并编码得到中断号（中断类型号）；操作系统按中断号调出相应的中断服务程序。
  • 教材简答(12)：中断类型号放在 I/O 总线数据线上而不是地址线上——它是标识"中断原因/来源"的信息、需要从控制器传给 CPU，属"数据"；地址线只用于定位存储单元/端口。
  • 名解候选：中断源、中断号（中断类型号）、中断请求寄存器、可编程中断控制器、中断屏蔽字、中断响应优先级、中断处理优先级、中断服务程序。

考点92总线性能计算（自建）S2025.04、教材习题▼
92.1 通用口径（四概念）
  • 三个概念先分清：时钟频率（每秒多少时钟周期，MHz）、数据传输率（每秒实际传多少次，MT/s、GT/s）、带宽（每秒传多少数据量，MB/s、GB/s）。
  • 工作频率 = 时钟频率 × 倍数（默认 1；倍数=1 时传输速率数值＝工作频率＝时钟频率）。
  • 总线带宽 = 工作频率 × 数据宽度[B]。
  • 单位对应：MHz × B → 数值即 MB/s；GHz × B → 数值即 GB/s；计算前先统一单位。
92.2 处理器总线（前端总线 FSB）
  • 从 Pentium Pro 起 FSB 采用 4 倍并发（Quad Pumped）技术：每个总线时钟周期传 4 次数据 → 数据传输速率 = 时钟频率 × 4。
  • 例：时钟频率 333MHz → 数据传输速率 1333MT/s（1.333GT/s，习惯称"1333MHz"）。
  • 2025.04 计算28(1)：333MHz×4 = 1332MHz（或习惯写 1333MHz）；带宽 = 1332MHz（或 1333MHz）× 64 位/8 = 10.656GB/s（或 10.664GB/s）。
  • 教材题7 同款：工作频率 1333MHz、64 位 → 带宽 = 1333 × 8 = 10.664GB/s。
92.3 QPI 总线
  • 20 条数据线；每次传输 20 位数据中有效数据 16 位，其余 4 位用于循环冗余校验（CRC）；双向（发送的同时可接收），每个时钟周期传 2 次数据。
  • 速度 = 时钟频率 × 2（单位 GT/s，也称 QPI 工作频率）。
  • 总带宽公式：总带宽 = 每秒传输次数 × 每次传输的有效数据[B] × 2。
  • 2025.04 计算28(2)：2.4GHz × 2 = 4.8GT/s（工作频率 4.8GT/s）；总带宽 = 4.8GT/s × 16位/8 × 2 = 19.2GB/s。
  • 教材题8：QPI 频率 6.4GT/s 时总带宽 = 6.4 × 2B × 2 = 25.6GB/s。
92.4 存储器总线
  • 带宽 = 传输速率(MT/s) × 数据宽度[B]；总带宽 = 总线带宽 × 通道数；DDR 在时钟上升/下降沿各传一次（533MHz × 2 = 1066MT/s）。
  • 教材题7：DDR3-1333——1333MT/s × 64位/8 = 10.664GB/s，3 通道总带宽 = 31.992GB/s；DDR3-1066——1066 × 8 = 8.528GB/s，×3 = 25.584GB/s（教材图口径 1066M×8B=8.5GB/s、×3≈25.6GB/s）。
92.5 I/O 总线（PCI-e）——串行、带编码
  • PCI-e×n = 具有 n 个通路的链路；1.0/2.0 用 8b/10b 编码（每 8 位数据编码成 10 位，有效率 8/10）；3.0/4.0/5.0 用 128b/130b。
  • 总带宽公式：总带宽 = 速率 × 2（双方向）× 编码效率 × 1/8（bit→B）。
  • PCI-e 1.0（单通路各方向 2.5Gb/s）：2.5 × 2 × 8/10 × 1/8 = 0.5GB/s/通路 → ×8 = 4GB/s，×16 = 8GB/s，×32 = 16GB/s（教材题9：×8、×32 两问；也可用比例法 4×4=16）。
  • PCI-e 3.0（8Gb/s）：8 × 2 × 128/130 × 1/8 ≈ 1.969GB/s/通路。

92.7 易错 QPI 别忘"×2 双向"：4.8GT/s × 2B × 2；用"16 位有效数据"=2B，不是 20 位。 PCI-e 的 8b/10b 写成"×8/10"，最后还要 ×1/8 把 bit 换成 byte。 存储器总线"总带宽"=单通道带宽 × 通道数；DDR 的 ×2 已体现在 MT/s（533MHz→1066MT/s）里，别重复乘。 FSB 的 4 倍并发：333MHz×4=1332MHz（习惯 1333MHz）——两种写法阅卷都认。

93.1 中断过程两阶段

93.2 中断服务程序三阶段（2026.04 填空20）
阶段主要工作
准备阶段把寄存器现场保存到栈上；按需（要响应新中断时）：①保存当前中断屏蔽字 ②设置新屏蔽字（指定处理阶段允许响应哪些中断源）③开中断——不需要响应新中断时可省略这三步
处理阶段从中断控制器读出中断号 → 按中断号查询并调用相应中断服务：先通知设备"中断已收到"、清除中断请求，再按设备具体功能处理（与设备紧密相关，通常作为设备驱动程序的一部分注册）
恢复阶段关中断、恢复现场和旧屏蔽字，最后执行中断返回指令（同时自动恢复处理器的中断使能位）
  • 填空口径：三阶段 = 准备、处理、恢复（不要写成"结束"）。
93.3 多重中断（中断嵌套）
  • 定义：中断处理过程中来了优先级更高且允许响应的新中断，CPU 暂停当前中断服务程序、转去处理新中断——称多重中断或中断嵌套。
  • 实现依靠栈：中断响应时把断点和程序状态字 PSW 压栈；返回时从栈顶取断点——后进先出。
  • 嵌套条件：当前中断服务程序所设置的屏蔽字对新中断"开放"（对应屏蔽位允许响应）。
用户进程 → 1# 中断（断点 K1+1、PSW1 压栈） → 处理中 2# 中断（K2+1、PSW2 压栈）→ 处理中又被 3# 中断 → 3# 返回先回到 2# 的断点 → 再依次回到 1#、用户进程 93.4 关中断的时机（教材简答(7)）
  • 为什么保护现场和恢复现场时必须关中断：若允许中断，新中断会打断正在进行的现场保护/恢复 → 现场状态不一致甚至出错。
  • 时机归纳：
中断响应阶段：硬件关中断 准备阶段：按需开中断（允许嵌套） 恢复阶段：先关中断 → 恢复现场 → 中断返回（自动恢复中断使能位）
  • 名解候选：多重中断、中断嵌套、断点保护、现场保护、（中断）响应与处理过程。

考点94中断/DMA 开销计算（自建）S2026.04、教材习题▼
94.1 计算框架（大纲"简单应用"：三种方式 CPU 开销比较） 中断间隔 t = 缓存器容量（折算成字节）÷ 数据传输率 每次中断开销 T = 中断响应与处理周期数 ÷ CPU 主频 I/O 服务占用率 = T ÷ t（传送期间的占比） 若设备只有一部分时间在传送：平均占用率 =（T ÷ t）× 设备工作时间占比
  • 判断能否用中断方式：每次中断开销远小于中断间隔才可以；T≥t 时 CPU 被 I/O 拖垮。
  • 三种方式开销口径：程序查询方式 CPU 用于 I/O 的时间为 100%（忙等待）；中断方式外设准备数据期间 CPU 可执行其他进程，只有当设备效率很低时才能大幅降低 CPU 的 I/O 开销；DMA 方式 CPU 只在初始化和"结束中断"时介入。
94.2 例6.3（中断方式，硬盘）
  • 设定：32 位单核 CPU 3GHz；硬盘传输带宽 128MB/s；控制器中 512B 数据缓存；中断方式每次传 512B；CPU 从 I/O 端口读一个字需 24 个时钟周期；系统调用开销 3µs、阻塞/调度 1.5µs、中断响应并调出服务程序 0.5µs、唤醒返回 3µs。
  • 单次中断数据处理时间：512B ÷ 128MB/s = 4µs；
  • 读 512B 数据：512B ÷ 4B/字 × 24 周期 = 3072 周期 = 3072 ÷ 3GHz = 1µs；
  • 一轮 4KB = 8 次中断，每轮 = 3 + (4+0.5+1)×8 + 3 = 50µs；
  • 硬盘工作时间占比 = 4×8 ÷ 50 = 64% → 实际数据传输率 = 128 × 64% = 81.92MB/s；
  • 进程 B 时间占比 = (4−1.5)×8 ÷ 50 = 40%。
94.3 例6.4（DMA 方式）
  • 每次 4KB：传 4KB = 4KB ÷ 128MB/s = 32µs；一轮 = 3 + 32 + 0.5 + 3 = 38.5µs；硬盘占比 = 32/38.5 = 83.12% → 实际传输率 106.39MB/s；B 占比 = 30.5/38.5 = 79.22%。
  • 每次 32KB：传 32KB = 256µs；一轮 = 3 + 256 + 0.5 + 3 = 262.5µs；占比 = 97.52% → 实际传输率 124.83MB/s；B 占比 = 254.5/262.5 = 96.95%。
  • 对比结论：DMA 比中断方式硬盘实际传输率提升约 29.88%，B 占比达约 1.98 倍——高速外设不适合中断方式（中断频繁、开销大），适合 DMA。
94.4 教材题13（打印机）
  • 6 页/min × 50 行 × 80 字符 = 24000 字符/min = 400 字符/s → 中断间隔 = 1/400 s = 2.5ms；
  • 每次中断响应+处理 = 1000 周期 ÷ 500MHz = 2µs ≪ 2.5ms → 可以采用中断控制方式（占用率约 0.08%）。
94.5 教材题14（16 位缓存器外设）
  • 16 位缓存器 = 2B；
  • 20KB/s：中断间隔 = 2B ÷ 20KB/s = 100µs，开销 = 500 周期 ÷ 500MHz = 1µs → 1% ≪ 100%，可以用中断方式；
  • 2MB/s：中断间隔 = 2B ÷ 2MB/s = 1µs = 开销 → 占用率 100%，不可以（CPU 全部耗在 I/O 上）。
94.6 2026.04 分析设计29（中断主机占用率）
  • 题：500MHz 主频；磁盘控制器 16B 数据缓存；磁盘传输速率 4MB/s；中断方式每次传送开销 500 个时钟周期；硬盘仅用 5% 的时间进行传送；求主机占用率。
  • 中断间隔 = 16B ÷ 4MB/s = 4µs；每次开销 = 500 ÷ 500MHz = 1µs（1µs<4µs，数据不会丢失）；
  • 传送期间占用率 = 1/4 = 25%；硬盘只在 5% 时间传送 → 主机占用率 = 25% × 5% = 1.25%。
94.7 教材题15（DMA 传送对指令速度的影响）

  • 指令执行速度降低 12.5%。

系统概述
考点1：存储程序 = 程序和数据都先送主存、启动后自动逐条取指并执行——不是"程序放在硬盘上"。 考点2：五大部件 = 运算器、控制器、存储器、输入设备、输出设备——寄存器是 CPU 内部部件，不单列。 考点3：PC 存"下一条"指令地址、IR 存当前指令；"状态计数器"是编造名词。 考点3：地址线传地址、数据线传数据、控制线传控制信息——CPU 访存先送地址和读/写命令，再经数据线传数据。 考点4：操作码 = 做什么操作，地址码 = 操作数在哪——两个字段的功能别写反。 考点5：六步：取指→译码→取源操作数→执行→存结果→算下条指令地址；PC+1 发生在取指之后。 考点6：翻译程序 = 汇编、编译、解释——链接程序不属于翻译程序。 考点7：源程序→可执行文件：预处理→编译→汇编→链接；.i/.s 是文本文件，.o 是二进制目标文件。 考点8：ISA = 软硬件之间的"桥梁"（接口的完整定义）；微体系结构 = 处理器内部怎么实现——两个层次别混。 考点9：操作系统、编译器、DBMS = 系统软件；Office、QQ、播放器 = 应用软件。 考点11：吞吐率 = 单位时间完成的工作量；响应时间 = 单个任务从开始到完成的时间——CPU 性能只算用户 CPU 时间。 考点12：主频高 ≠ 更快——把 CPI 算进执行时间再比；MIPS 不能跨指令集比较。 编码与运算
考点14：BCD 按"四位一组"拆——(10011001)₂ = 153 而 (10011001)BCD = 99，数制比较先分清是不是 BCD。 考点15：数制比较一律"按权展开"化成十进制再比；十六进制后缀 H、八进制后缀 O，别记反。 考点18/19：负数补码 = 模 − |X|；三个"取反加 1"的取反范围不同——求相反数要连符号位一起取反。 考点20：8 位带符号范围 −128 ~ +127（负数端多一个数）；判溢出先看"同号相加、结果符号改变"。 考点21/22：阶码 = 指数 + 127（求值 −127）；尾数 1.F 的"1"隐含不写。 考点28/29/30：OF 看有符号、CF 看无符号；减法时 CF = ¬Cout；判溢出不看进位、看 OF 或范围。 考点31：对阶只准"小向大"；规格化左移尾数→指数减，右移→指数加。 考点32："阶码部件能做乘除"是陷阱——阶码只做加减和比较。 考点15：进制转换——整数"除基取余、逆序排列"，小数"乘基取整、顺序排列"，两个方向别搞反。 考点18：补码的目的 = 统一加减法电路、简化硬件设计；0 的补码唯一（原码、反码的 0 有两种）。 考点26：小端 = 低有效字节存低地址，大端相反——口诀"高大"（高字节对低地址 = 大端）。 指令与链接
考点37：Intel↔AT&T 三个坑——操作数方向对调、丢 $ 和 %、地址括号位置（8(%ebp,%edx,4)）。 考点40：INC/DEC 不碰 CF；MUL/IMUL 只碰 CF/OF；DIV/IDIV 什么标志都不碰。 考点43："SP 内容 = 栈内数据个数"是陷阱——SP 永远是地址；PUSH 先减后存、POP 先取后加。 考点44：LEA 不访存——leal 取"算出来的地址"，movl 取"该地址里的内容"。 考点46：无符号比较记 a/b（看 CF），带符号比较记 g/l（看 SF⊕OF）——写反直接丢分。 考点57/60：局部变量不是符号；static 的"本地符号"仍在符号表——两句话都对，别互否。 考点62："两个 COMMON"不报错（取占空间最大者）；只有"强+强"才报链接错误。 考点58：.data / .bss 的分界 = 初值是否为 0（int z = 0; 进 .bss）。 考点67：流水线单条指令时间不缩短、吞吐率提高；总时间 = (M−1+N)×T，别写成 N×T。 考点47：call 压栈的返回地址 = call 的下一条指令地址；ret 取出返回地址回到调用点。 考点48：值传递只复制实参的值、形参变化不影响实参；传指针（地址）才能修改实参所指对象——指针存的是地址，不是变量的值。 考点49：while 先判断后执行（可能一次都不执行）；do~while 先执行后判断（至少执行一次）。 考点50：A[i] 地址 = 首地址 + i × 元素字节数——short×2、int×4，别漏乘元素长度；首地址 = A[0] 的地址。 考点51：成员偏移必须是自身大小的整数倍、总大小补齐到最大成员的整数倍——调整成员声明顺序可省空间。 考点53：movl 写 32 位寄存器时高 32 位自动清零（等价 movzlq）；movsbq/movswq/movslq 是符号扩展、movzbq/movzwq 是零扩展。 考点63：静态链接 = 生成可执行文件时合并库代码（文件大、升级要重编）；动态链接 = 加载/运行时链接共享库（便于共享与升级）。 考点64：程序 = 静态的代码+数据集合；进程 = 程序的一次运行活动（动态、用 PID 标识）——一个程序可对应多个进程。 考点66：非法操作码、除 0、溢出、页故障 = 内部异常（指令执行引起）；时钟到时、网络包到达、外设请求 = 外部中断（外部事件引起）。 存储
考点68/69：易失 = 主存 + cache；交换单位 cache↔主存是"块"、主存↔外存是"页"；cache 缺失硬件处理、缺页软件处理。 考点72：行数一变行号位数就变（16 行→4 位、32 行→5 位），标记位数随之反向变化。 考点74：组数 = 行数 ÷ 路数；通写无修改位、回写加修改位；LRU 位数 = log₂路数。 考点78：先算块号（地址÷块大小）再 mod 组数；列优先访问命中率可能为 0（同组互替）。 考点79：地址三段分解（32 位 = 3 位选条 + 3 位选片 + 26 位片内）；"64M×8 位"芯片容量 = 64MB。 考点81：缺页却 TLB 命中不可能；越权（权限不符）≠ 越界（访问空洞）≠ 越级（用户访内核）。 考点69：速度层次 寄存器 > cache > 主存 > 硬盘——越靠近 CPU 越快、容量越小、越贵；主存是层次结构的核心存储器。 考点70：时间局部性 = 同一单元短期内被重复访问；空间局部性 = 临近单元将被访问——单个变量谈"空间局部性"没有意义。 I/O
考点82："异步性"不是"同步性"；运行时系统不是内核空间 I/O 软件；与设备无关层不含中断服务程序。 考点83：链条背全：printf → write → 陷阱指令 → system_call → sys_write；两次上下文切换 = 去内核 + 回用户。 考点84：减少系统调用靠"用户空间的流缓冲区"（不是内核磁盘高速缓存）。 考点87：中断控制链条"启动第一个数据→阻塞→并行→中断→服务程序启动后续数据"；DMA 整块传完才发中断。 考点88：鼠标/扫描仪/数字化仪/控制杆 = 输入；绘图仪/打印机/显示器 = 输出。 考点90："节约主存地址空间"的是独立编址；统一编址关键词 = 共用指令 → 虚拟存储保护。 考点91：断点由 CPU 保存（下条指令地址）、现场由中断服务程序保存；响应优先级 = 谁先被响应，处理优先级 = 屏蔽字动态设定。 考点92：QPI 别忘"×2 双向"；PCI-e 编码效率后还要 ÷8；DDR 的 ×2 已含在 MT/s 里，别重复乘。 考点93：三阶段 = 准备 / 处理 / 恢复——写"结束阶段"不得分。 考点94：先统一单位（1MB/s = 1B/µs）；"16 位缓存器"= 2B；平均占用率要再乘设备工作时间占比（2026.04 的 5%）。
