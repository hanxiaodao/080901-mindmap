## 第一章 计算机系统概述

### 一、名词解释（40）

1. **中央处理器（CPU）**：中央处理器是计算机系统的核心部件，负责执行程序中的指令、处理数据，并控制计算机的各个部件协调工作。CPU 由控制部件、运算部件（ALU）和各类寄存器互连组成。
2. **算术逻辑部件（ALU）**：CPU 中的运算部件，在控制单元产生的 ALUop 控制信号下，对输入端 A、B 完成基本的逻辑运算和定点数加减运算；定点乘除和浮点运算需由加法器、ALU 和移位器共同实现。
3. **通用寄存器**：CPU 内部的通用寄存器组，用于临时存放从主存取来的数据、运算结果或地址，可被 CPU 快速访问；指令暂存在 IR，当前访问的主存地址暂存在 MAR。
4. **程序计数器（PC）**：一个特殊的寄存器，用于存储下一条将要执行的指令的地址。顺序执行时，PC 加上当前指令的长度（字节数）；执行跳转、调用或返回等指令时，PC 被置为目标地址。
5. **指令寄存器（IR）**：用于暂存当前正在执行的指令。当 CPU 从主存储器中读取一条指令后，会将其放入指令寄存器中，解码并执行。
6. **控制器**：CPU 中的另一个关键组件，负责从主存储器中取出指令，对指令进行译码，并根据指令的要求，有序地、协调地指挥和控制计算机各部件自动工作。
7. **主存储器**：计算机中的主要存储部件，用于存储程序和数据。CPU 可以直接访问主存储器中的数据，而不需要通过其他外部设备。
8. **总线**：计算机各部件之间传输信息的公共通道，由导线组成，包含地址线、数据线和控制线，用于在 CPU、主存储器、I/O 设备之间传输地址、数据和控制信息。
9. **主存地址寄存器（MAR）**：用于存放 CPU 欲访问的主存单元的地址。取指令时地址来自程序计数器（PC），取数/存数时地址由指令中的地址码字段和寻址方式形成。MAR 与主存储器地址译码电路相连，为 CPU 访问主存提供所要访问的主存单元的地址。
10. **主存数据寄存器（MDR）**：用于暂存从主存储器读出的一条指令或一个数据字，或准备写入主存储器的字。MDR 与主存储器数据总线相连，与 MAR 配合使用，实现 CPU 与主存储器之间的数据交换。
11. **机器指令**：CPU 能直接识别并执行的指令，由操作码和操作数地址码组成。每一条指令完成一个基本的操作，如数据传送、算术运算等。
12. **指令操作码**：机器指令中的一部分，用于指定该指令所要执行的操作类型，如加法、减法、存储等。
13. **高级程序设计语言**：一种接近于人类自然语言和数学语言的程序设计语言，易于编写和理解，经过编译或解释后能转换成机器语言执行。
14. **汇编语言**：一种用助记符表示机器指令的低级程序设计语言，需经汇编程序翻译成机器语言才能执行。
15. **机器语言**：直接用二进制代码指令表达的计算机语言，是计算机唯一能直接识别和执行的语言。
16. **机器级语言**：通常指的是与特定机器或处理器直接相关的低级编程语言，包括机器语言和汇编语言。
17. **源程序**：用高级程序设计语言或汇编语言编写的、尚未经翻译程序转换为机器语言目标程序的程序。
18. **目标程序**：源程序经翻译程序转换后得到的目标语言程序。目标语言可以是汇编语言或机器语言；目标程序通常还需经过汇编、链接等处理才能成为可执行文件。解释程序逐句解释执行，不生成独立的目标程序。
19. **编译程序**：一种将高级程序设计语言编写的源程序翻译成目标程序的软件工具。编译过程通常包括词法分析、语法分析、语义分析、优化和代码生成等阶段。
20. **解释程序**：一种将高级语言源程序逐句解释并立即执行的软件工具；它不生成独立的目标程序，通常比编译方式慢。
21. **汇编程序**：一种将汇编语言源程序翻译成机器语言目标程序的软件工具。汇编过程包括将汇编语言指令转换为机器语言指令，并分配内存地址等。
22. **语言处理系统**：提供程序编辑器和各类翻译转换软件的工具包，包括编辑器、预处理程序、编译器、汇编器、链接器等。
23. **设备控制器**：计算机中的一个硬件部件，负责控制和管理外部设备（如打印机、磁盘驱动器等）与 CPU 之间的数据传输。
24. **最终用户**：直接使用计算机系统和应用程序的个人或组织，他们通过用户界面与计算机进行交互，完成各种任务。
25. **系统管理员**：负责管理和维护计算机系统的专业人员，他们负责安装、配置、监控和维护计算机硬件、软件和网络等。
26. **应用程序员**：负责开发、编写和维护各种应用程序的专业人员，他们使用高级程序设计语言进行程序设计，以满足用户的特定需求。
27. **系统程序员**：负责设计、开发和维护计算机系统软件的专业人员，他们负责编写操作系统、编译器、数据库管理系统等核心软件。
28. **指令集体系结构（ISA）**：软件与硬件之间的界面，定义一台计算机可以执行的所有指令的集合，以及每条指令的操作、操作数地址空间和操作数类型；CPU 如何实现这些指令属于微体系结构。
29. **微体系结构（Microarchitecture）**：计算机处理器设计的一个关键部分，它定义了处理器内部各个组件的结构、功能以及它们之间的交互方式。微体系结构决定了处理器如何执行指令、管理数据、处理中断等，从而影响了处理器的性能、功耗和效率。
30. **透明（Transparency）**：在计算机科学中，透明通常指的是某个方面对使用者是不可见的或者是不需要考虑的。例如，内存管理的某些细节对程序员可能是透明的，意味着程序员不需要直接处理这些细节，而由操作系统或硬件自动管理。
31. **响应时间（Response Time）**：从作业提交开始到作业完成所用的时间，是衡量计算机系统性能的基本指标之一；类似概念有执行时间和等待时间。
32. **吞吐率（Throughput）**：单位时间内所完成的工作量，反映系统处理任务的整体效率；类似概念是带宽，表示单位时间内传输的信息量。
33. **用户 CPU 时间（User CPU Time）**：CPU 真正用于运行用户程序代码的时间。系统 CPU 时间则是为了执行用户程序而需要 CPU 运行操作系统程序的时间。
34. **时钟周期（Clock Cycle）**：CPU 主脉冲信号的宽度，是 CPU 中最小的时间单位；一条指令通常需要多个时钟周期。
35. **主频（Clock Rate）**：处理器每秒钟的时钟周期数，通常以赫兹（Hz）或兆赫兹（MHz）、吉赫兹（GHz）为单位表示。主频越高，处理器执行指令的速度通常越快。
36. **CPI（Cycles Per Instruction）**：执行一条指令所需的平均时钟周期数，CPI = Σ(CPI_i × F_i)，其中 CPI_i 是第 i 类指令的周期数，F_i 是该类指令在程序中的比例。CPU 执行时间 = 指令条数 × CPI × 时钟周期，不能只看 CPI 判断快慢。
37. **基准程序（Benchmark Program）**：一组用于测试和评估计算机系统性能的预定义程序和测试套件。通过运行这些基准程序，可以比较不同系统的性能，并找出性能瓶颈。
38. **MIPS（Millions of Instructions Per Second）**：每秒执行多少百万条指令，反映机器执行定点指令的速度。MIPS 不能准确比较不同机器的性能，因为不同机器的指令集、指令功能、CPI 和时钟周期可能不同。
39. **峰值 MIPS（Peak MIPS）**：选取一组指令组合，使平均 CPI 最小，由此得到的 MIPS 称为峰值 MIPS。有些制造商把峰值 MIPS 直接当作 MIPS，实际性能通常比标称性能差。
40. **相对 MIPS（Relative MIPS）**：用于比较不同处理器或系统性能的 MIPS 指标。它通常是将一个系统的 MIPS 值除以另一个基准系统的 MIPS 值，从而得到一个相对性能的比值。

### 二、简答题（7）

**1. 冯·诺依曼计算机由哪几部分组成？各部分的功能是什么？**

解答：冯·诺依曼计算机主要由五大部分组成：输入设备、输出设备、运算器、控制器和存储器。

- 输入设备：用于接收用户输入的数据和指令，如键盘、鼠标等。
- 输出设备：用于展示计算机处理后的结果，如显示器、打印机等。
- 运算器：执行各种算术和逻辑运算。
- 控制器：控制计算机的各个部件协同工作，负责指令的读取、解释和执行。
- 存储器（主存）：存放程序和数据；外存是辅助存储器，需调入主存后才能被 CPU 访问。

**2. 什么是“存储程序”工作方式？**

解答：“存储程序”工作方式是指将程序和数据以二进制代码形式预先存放在计算机的主存中，然后计算机在运行时从主存中取出指令并加以执行。这种方式使得计算机能自动、连续地执行程序，从而大大提高了计算机的工作效率。

**3. 一条指令的执行过程包含哪几个阶段？**

解答：一条指令的执行过程通常包含以下几个阶段：

- 取指令：根据 PC 从存储器取出指令，并计算下一条指令地址（PC ← PC + 当前指令长度）。
- 分析指令：对指令操作码进行译码，产生相应的控制信号。
- 执行指令：根据控制信号进行运算、地址计算或访存等操作。
- 存储结果：将结果写回寄存器或存储器。

**4. 计算机系统的层次结构如何划分？**

解答：按教材图 1.10，从应用问题到硬件可划分为以下抽象层：

- 应用（问题）
- 算法
- 编程（语言）
- 操作系统/虚拟机
- 指令集体系结构（ISA）
- 微体系结构
- 功能部件/RTL
- 电路
- 器件

其中，ISA 是软件与硬件之间的界面；语言处理系统（编辑器、编译器、汇编器、链接器等）是独立的软件层，不属于操作系统层。操作系统提供人机交互界面和系统调用服务例程，并对底层硬件进行抽象。

**5. 计算机系统的用户可分为哪几类？每类用户工作在哪个层次？**

解答：按照在计算机上完成任务的不同，使用计算机的用户可分为四类：

- 最终用户：直接使用计算机和应用程序完成具体任务的人（如使用炒股软件的股民、玩游戏的人、财会人员），工作在最上面的应用程序层。
- 系统管理员：利用操作系统、数据库管理系统等提供的功能对系统进行配置、管理和维护，以建立高效合理的系统环境供用户使用，工作在操作系统层（操作系统虚拟机）。
- 应用程序员：大多用高级语言开发应用程序，工作在提供编译器、解释器等翻译程序的语言处理系统层（高级语言虚拟机），因而也称为高级语言程序员。
- 系统程序员：开发操作系统、编译程序、数据库管理系统等系统软件，工作在 ISA 层，所看到的是配置了指令系统的机器语言机器，因而也称为机器语言程序员。

注：教材另有“汇编语言程序员工作在汇编语言虚拟机层”的提法；同一个人在不同场合可以充当不同的用户角色。

**6. 程序的 CPI 与哪些因素有关？**

解答：程序的 CPI（每条指令的时钟周期数）与以下因素有关：

- 指令类型及其在程序中的比例：CPI = Σ(CPI_i × F_i)，不同指令的 CPI 不同，比例变化会改变程序平均 CPI。
- 指令的执行顺序与流水线效率：数据相关、控制相关等可能引入停顿，从而影响实际 CPI。
- 数据的存取方式：cache 命中率、内存访问延迟等会影响访存指令的等效 CPI。
- 程序的优化：优化可能减少指令条数或改变指令组合，但也可能提高 CPI；不能一概认为优化会降低 CPI。教材例 1.3 中优化后 CPI 由 1.57 升至 1.73，但程序执行时间减少。

**7. 为什么说性能指标 MIPS 不能很好地反映计算机的性能？**

解答：MIPS（每秒百万条指令数）是一个衡量计算机性能的指标，但它并不能很好地反映计算机的性能，原因如下：

- 不同机器的指令集不同，指令功能也不同：在 M1 上一条指令完成的功能，在 M2 上可能需要多条指令，因此相同指令条数所完成的功能可能不同。
- 不同机器的 CPI 和时钟周期不同，同一条指令在不同机器上所用的时间也不同。
- MIPS 只反映定点指令的执行速度，不能反映浮点、I/O、内存访问等性能，也不能准确比较不同 ISA 的机器。

因此，虽然 MIPS 是一个有用的性能指标，但它并不能全面反映计算机的实际性能。在评估计算机性能时，还需要考虑其他因素，如响应时间、吞吐量、功耗等。

## 第二章 数据的表示和运算

### 一、名词解释（21，原题表述为“给出以下概念的解释说明”）

1. **真值**：数学上的值，即我们实际想要表示的数，不考虑计算机内部如何表示。
2. **机器数**：在计算机内部用来表示数值的二进制编码。它可能由于编码方式（如原码、补码等）和机器的特性而有所不同。
3. **数值数据**：可以表示数量多少、可比较大小的数据，分为整数和实数；整数又分为无符号整数和带符号整数，实数用浮点数表示。
4. **非数值数据**：没有大小之分、不表示数量多少的数据，主要包括字符数据和逻辑数据。
5. **无符号整数**：一个非负的二进制数，它只表示大小，不表示正负。
6. **带符号整数**：必须用一个二进位表示符号。现代计算机中带符号整数都用补码表示，符号位和数值位一起参加运算；n 位带符号整数的范围为 −2^{n−1} ~ 2^{n−1}−1。
7. **定点数**：一种数值表示方法，其中小数点位置是固定的。定点数主要用于表示整数或小数。
8. **浮点数**：一种数值表示方法，其中小数点位置可以浮动。它由数符、尾数（mantissa）和阶码（exponent）组成，用于表示非常大或非常小的数。
9. **尾数**：浮点数中用于表示数值大小的部分。
10. **阶和阶码**：阶是浮点数中小数点实际位置与默认位置之间的偏移量。阶码则是这个偏移量的编码表示。
11. **溢出**：计算机在运算过程中，结果超出了它能表示的范围。这可能导致不正确的结果或错误。
12. **规格化数**：尾数满足规定形式的浮点数。基数为 2 时，原码规格化形式为 ±0.1bb…b×2^E；规格化可增加有效数位、保证表示唯一性，表示范围由阶码决定。
13. **左规**：浮点数运算结果出现 ±0.0…0bb…b×2^E 时，尾数每左移一位、阶码减 1，直到尾数满足规格化形式；左规可能使阶码下溢，但左规本身不等于下溢。
14. **右规**：浮点数运算结果的有效数位进到小数点前面（按 1/2≤|M|<1 的口径，即 |M|≥1）时，尾数每右移一位、阶码加 1，直到满足规格化形式；右规可能使阶码上溢。
15. **ASCII 码**：一种 7 位字符编码，用 0～127 表示英文字母、数字、标点和控制字符；在计算机中通常占 8 位（最高位可作校验位或置 0）。
16. **汉字输入码**：用户通过键盘等设备输入汉字时所使用的编码，如拼音、五笔等。
17. **汉字内码**：计算机内部存储、处理和传输汉字时使用的编码。不同系统可采用不同内码；GB2312 主要是国标码/交换码，GBK、UTF-8 也可作为内码使用。
18. **字长**：CPU 内部用于整数运算的数据通路宽度，通常为 32 位或 64 位；它决定了 CPU 一次能处理的整数位数。
19. **大端方式**：一种数据存储方式，其中高位字节存储在内存的低地址端，低位字节存储在内存的高地址端。
20. **小端方式**：另一种数据存储方式，其中低位字节存储在内存的低地址端，高位字节存储在内存的高地址端。
21. **ALU（算术逻辑单元）**：算术逻辑部件，完成基本的逻辑运算和定点数加减运算；定点乘除和浮点运算需由加法器、ALU 和移位器共同实现，ALU 的核心部件是加法器。

### 二、简答题（5）

**1. 为什么计算机内部采用二进制表示信息？**

解答：

- 二进制只有 0 和 1 两种状态，这与计算机中的逻辑电路的开关状态一致，使得信息表示和计算非常直接和简单。
- 二进制数的运算规则简单，使得计算机在进行运算时更加高效。
- 二进制的两个符号 0、1 正好与逻辑命题的“真/假”对应，便于用逻辑门实现逻辑运算和程序中的逻辑判断。

**2. 既然计算机内部所有信息都用二进制表示，为什么还要用到十六进制或八进制数？**

解答：虽然计算机内部所有信息都用二进制表示，但使用十六进制或八进制数是为了方便人类理解和操作。十六进制和八进制数的每一位可以对应多个二进制位，这使得在表示较长的二进制数时，十六进制或八进制数更加简洁，便于阅读和书写。在程序设计和调试中，使用十六进制或八进制数可以更方便地查看和操作内存地址和数据。

**3. 在浮点数的基数和总位数一定的情况下，浮点数的表示范围和精度分别由什么决定？**

解答：浮点数的表示范围和精度分别由阶码和尾数决定。阶码决定了浮点数的范围，即能表示的最大和最小数值；而尾数决定了浮点数的精度，即数值的精确度或小数部分的位数。

**4. 为什么要对浮点数进行规格化？有哪两种规格化操作？**

解答：对浮点数进行规格化是为了提高浮点数的表示精度、统一浮点数的表示形式，并便于浮点运算的实现（浮点加减、乘除运算后都要进行规格化）。

规格化就是把尾数调整为规定的形式：当尾数用原码表示时，要求 1/2 ≤ |尾数| < 1（即形式为 ±0.1bb…b）；用补码表示时，要求符号位与最高数值位不同。

两种规格化操作的方向和触发条件如下：

- 左规：当运算结果形如 ±0.0…0bb…b×2^E、尾数绝对值小于 1/2 时，尾数左移一位、阶码减 1，直到满足规格化要求。左规可能引起阶码下溢，但左规本身不是下溢。
- 右规：当运算结果的有效数位进到小数点前面（按 1/2≤|M|<1 的口径，即 |M|≥1）时，尾数右移一位、阶码加 1。右规可能引起阶码上溢。

记忆要点：**左移尾数→阶码减，右移尾数（尾数溢出）→阶码加**，方向别记反。

**5. 为什么计算机处理汉字时会涉及不同的编码（如输入码、内码、字模码）？说明这些编码中哪些用二进制编码，哪些不用二进制编码，为什么？**

解答：计算机处理汉字时会涉及不同的编码，如输入码、内码和字模码，是因为汉字数量庞大，需要有效的编码方式来存储、传输和显示。这些编码中，输入码如拼音码、五笔码等不是用二进制编码的，因为它们是为了方便用户输入汉字而设计的，具有特定的输入规则和逻辑。而内码和字模码则是用二进制编码的。内码是计算机内部用于存储和传输汉字的唯一标识码，需要二进制编码来确保唯一性和计算机识别的准确性。字模码是用于显示汉字的字形信息，通常以二进制图像或点阵形式表示，因此也需要二进制编码。

## 第三章 程序的转换及机器级表示

### 一、名词解释（40）

1. **机器语言程序**：一种由二进制代码组成的程序，直接由计算机硬件执行的指令集合。
2. **汇编指令**：一种由助记符表示的机器指令，与机器语言一一对应，可被汇编器转换成对应的机器语言指令。
3. **汇编语言程序**：使用汇编语言编写的程序，以助记符形式表示的指令序列，需要经过汇编器转换为机器语言程序。
4. **汇编助记符**：汇编语言中表示操作码或操作数的符号，如 add、mov 等，用来代替机器指令的二进制编码。
5. **汇编程序**：将汇编语言程序转换成机器语言程序的程序，也称为汇编器。
6. **反汇编程序**：将机器语言程序转换回汇编语言程序的程序。
7. **机器级代码**：编译器/汇编器生成的、能被特定处理器直接执行的指令序列，包括机器指令及其操作数；汇编语言是它的符号表示。
8. **CISC**：复杂指令集计算机，指一种计算机架构，其指令集包含了多种复杂的指令。
9. **RISC**：精简指令集计算机，其指令数目少、指令格式规整且通常定长、只有 Load/Store 指令能访问存储器、使用大量通用寄存器。
10. **通用寄存器**：用于存储临时数据和地址的寄存器，通常用于存储计算过程中的中间结果。
11. **变址寄存器**：用于提供变址值的寄存器；变址值等于其内容乘以比例系数 S（非比例变址时 S=1），常用于数组、结构体等数据结构的访问。
12. **基址寄存器**：用于存储内存地址基址的寄存器，通常与变址寄存器一起使用，用于计算实际内存地址。
13. **栈指针寄存器**：用于存储栈顶地址的寄存器，用于实现函数调用和局部变量存储等操作。
14. **指令指针寄存器**：用于存放将要执行的下一条指令的地址的寄存器（IA-32 中为 EIP，x86-64 中为 RIP）。
15. **标志寄存器**：用于存放算术/逻辑运算结果状态标志的寄存器，如 ZF、SF、CF、OF 等，供条件转移指令使用。
16. **条件标志（条件码）**：标志寄存器中由算术/逻辑指令设置的状态位，如 ZF、SF、CF、OF；条件转移指令根据这些条件码决定是否跳转。
17. **寻址方式**：根据指令给定信息得到操作数或操作数地址的方式，例如立即寻址、寄存器寻址、相对寻址等。
18. **立即寻址**：直接将操作数的值嵌入到指令中。
19. **寄存器寻址**：指令中给出操作数所存放的寄存器的编号，指定寄存器的内容就是操作数。
20. **相对寻址**：以程序计数器 PC（IA-32 中为 EIP）的内容为基准，加上指令中给出的位移量 A 得到目标地址，即 LA=(PC)+A；多用于转移指令。
21. **存储器操作数**：指令中的操作数直接引用存储器中的数据。
22. **实地址模式**：为与 8086/8088 兼容而设置的工作模式；采用分段方式，最大寻址空间 1 MB，每段最大 64 KB，物理地址 = 段地址×16 + 偏移地址。
23. **保护模式**：一种 CPU 工作模式，操作系统可在其中对内存和其他资源进行保护和管理。
24. **有效地址**：操作数所在段的段内偏移地址，由基址、变址×比例因子、位移量等按寻址方式计算得到；在 IA-32 保护模式下，它与段寄存器内容一起形成线性地址。
25. **比例变址**：变址值等于变址寄存器内容乘以比例系数 S，即有效地址中包含 (I)×S，并可与基址、位移量组合，如 LA=(SR)+(I)×S+A。
26. **非比例变址**：比例系数为 1 的比例变址，变址值就是变址寄存器的内容，无须乘以比例系数；仍可与基址、位移量组合。
27. **比例系数（比例因子）**：比例变址中变址值的乘数 S，表示操作数的字节个数，通常取 1、2、4 或 8。
28. **MMX 指令**：Intel 处理器中用于多媒体处理的指令集。
29. **SSE 指令集**：Intel 处理器中的一种扩展指令集，用于实现单指令多数据（SIMD）操作。
30. **SIMD**：单指令多数据，一种并行计算的技术，能够同时处理多个数据。
31. **多媒体扩展通用寄存器**：SSE 指令集使用的 8 个 128 位专用寄存器 XMM0～XMM7，用于存放 SIMD 操作的数据。
32. **栈（Stack）**：一种后进先出（LIFO）的数据结构，用于临时存储函数调用的上下文和局部变量。
33. **调用者保存寄存器**：在函数调用过程中，由调用者负责保存和恢复的寄存器。
34. **被调用者保存寄存器**：在函数调用过程中，由被调用者负责保存和恢复的寄存器。
35. **帧指针寄存器**：用于指向当前函数调用的栈帧的寄存器。
36. **当前栈帧**：当前函数调用的栈帧，存储了函数的参数、局部变量和返回地址等信息。
37. **按值传递参数**：将参数的值传递给函数。
38. **按地址传递参数**：将参数的地址传递给函数，函数可以直接访问参数的值。
39. **嵌套调用**：一个函数调用另一个函数，而后者又调用其他函数，形成多层调用（如 P→Q→R）的过程。
40. **递归调用**：函数直接或间接地调用自身的过程。

### 二、简答题（8）

**1. 一条机器指令通常由哪些字段组成？各字段的含义分别是什么？**

解答：机器指令一般由操作码和地址码两部分组成。操作码指出操作类型；地址码给出操作数或操作数地址。IA-32 机器指令最多包含以下 5 个字段：

- 操作码：指示指令的操作类型。
- 操作数说明：包括操作数个数、操作数长度（8/16/32 位）等信息。
- 寻址方式：指定如何得到操作数或操作数地址。
- 立即数/位移量：指令中直接给出的常数或地址偏移量。
- 寄存器/存储器地址：指定参与操作的寄存器编号或存储器地址。

**2. 将一个高级语言源程序转换成计算机能直接执行的机器代码通常需要哪几个步骤？**

解答：按教材 §3.1.4「生成机器代码的过程」，通常分为 4 步：

1. 预处理：处理源程序中以 # 开头的命令（头文件包含、宏展开、条件编译等），生成 .i 文件。
2. 编译：将预处理后的源程序翻译成汇编语言程序，生成 .s 文件。编译器内部在这一步完成词法分析、语法分析、语义分析、代码优化和目标代码生成。
3. 汇编：由汇编程序把汇编语言源程序转换为可重定位的机器语言目标文件，生成 .o 文件。
4. 链接：由链接器把多个可重定位目标文件（含库函数目标文件）组合起来，生成可被计算机直接执行的可执行目标文件。

注意：不要答成「词法分析→语法分析→语义分析→代码生成→代码优化」——那是编译器内部的处理阶段，不是教材本题所问的 4 步；真题填空也按「预处理、编译、汇编、链接」考。

**3. IA-32 中的逻辑运算指令如何生成条件标志？移位指令可能会改变哪些条件标志？**

解答：在 IA-32 中，逻辑运算指令（NOT 除外，如 AND、OR、XOR、TEST）执行后使 OF=CF=0，ZF 和 SF 根据运算结果设置；NOT 不影响条件标志。移位指令可能改变 ZF、SF、CF 和 OF，具体取决于指令和移位量。

**4. 执行条件跳转指令时所用到的条件标志信息从何而来？请举例说明。**

解答：条件标志信息来自最近一条影响条件标志的指令（不一定紧邻条件跳转指令）。例如，CMP/TEST 等指令设置 ZF、SF、CF、OF 后，JZ 根据 ZF 是否为 1 决定是否跳转。

**5. 无条件跳转指令和调用指令的相同点和不同点是什么？**

解答：无条件跳转指令和调用指令的相同点是它们都可以改变程序执行的流程，使程序跳转到指定的地址执行。不同点在于无条件跳转指令只是改变 EIP（或 CS:EIP）；调用指令先把返回地址（CALL 下一条指令的地址）压入栈，并修改 ESP，再把目标地址装入 EIP（或 CS:EIP）。

**6. 按值传递参数和按地址传递参数两种方式有哪些不同点？**

解答：不同点在于：

- 按值传递参数会将参数的值复制给函数的形式参数，因此函数内部对形式参数的修改不会影响实际参数的值；
- 按地址传递参数则会将参数的地址传递给函数，函数内部对形式参数的修改会影响实际参数的值。

**7. 为什么在递归深度较深时递归调用的时间开销和空间开销都会较大？**

解答：每次递归调用都要在栈上建立新栈帧，保存返回地址、参数、局部变量和保存的寄存器，占用额外栈空间；同时每次调用/返回都要执行压栈、跳转、出栈等指令，递归深度大时时间和空间开销都显著增加。

**8. 为什么数据在存储器中最好按地址对齐方式存放？**

解答：许多计算机体系结构要求数据按边界对齐（如 4 字节 int 的地址应是 4 的倍数），对齐后一次总线访问即可完成；不对齐可能跨越两个存储单元，需要两次访问，降低效率。

## 第四章 可执行文件的生成与加载执行

### 一、名词解释（33）

1. **链接**：将多个可重定位目标文件以及所需的库文件组合起来，生成一个可执行目标文件或共享库文件的过程。
2. **可重定位文件**：单个模块经编译/汇编生成的目标文件，含代码、数据和重定位信息，代码从 0 开始，地址尚未最终确定，可在链接时与其他模块组合并重定位。
3. **可执行文件**：经过链接后，代码和数据在 ABI 规定的虚拟地址空间中的位置已经确定，含程序头表，可直接装入执行的文件。
4. **符号解析**：在链接过程中，将每个符号的引用与一个确定的符号定义建立关联的过程。
5. **重定位**：重新确定代码和数据的地址，并更新指令中被引用符号地址的操作。
6. **ELF 头**：可重定位目标文件、可执行文件和共享库文件开头的数据结构，描述文件类型、机器类型、入口地址、节头表/程序头表的位置和大小等信息。
7. **节头表**：描述可重定位目标文件中各节（section）的名称、类型、大小、在文件中的位置等信息；可执行文件也可以有节头表用于调试，但加载不依赖它。
8. **程序头表**：包含了可执行文件或共享库文件中各个程序段（segment）的信息，如加载地址、大小等。
9. **只读代码段**：在可执行文件中由 ELF 头、程序头表、.init、.fini、.text、.rodata 等组成的可装入段，访问权限为读/执行。
10. **可读/写数据段**：由 .data 节和 .bss 节组成的可装入段，存放可读/写的全局和静态变量，访问权限为读/写。
11. **全局符号**：在整个程序中都可见的符号，可以被其他文件引用。
12. **外部符号**：在当前文件中未定义，但在其他文件中定义的符号。
13. **本地符号**：仅在当前文件中可见的符号，对其他文件不可见。
14. **强符号**：函数名、已初始化且初值不为 0 的全局变量、初值为 0 的全局变量等；强符号不能多次定义，否则链接错误。多个模块出现同名弱符号/COMMON 符号时才以强符号为准。
15. **COMMON 符号**：未被分配位置的未初始化变量（通常是未初始化的全局变量），在符号表中用 COMMON 伪节表示；它允许多个模块重复定义，链接时按规则合并并分配存储空间。
16. **静态链接**：在链接阶段将静态库中被引用的目标模块合并到可执行文件中的链接方式。
17. **共享库文件**：包含可被多个可执行文件共享的代码和数据，可在程序装入或运行时映射到进程虚拟地址空间，供多个进程共享使用的文件。
18. **动态链接**：在程序装入或运行时将共享库文件动态装入内存并自动链接的链接方式。
19. **动态链接器**：负责在程序装入或运行时将共享库映射到进程地址空间、解析符号引用并完成重定位的系统程序。
20. **动态链接库**：以共享库形式组织，可在程序装入或运行时被动态链接器映射并链接到进程地址空间使用的库文件。
21. **进程**：计算机中正在运行的程序的实例，是操作系统进行资源分配和调度的基本单位。
22. **进程描述符**：操作系统中用于描述进程状态、地址空间、打开文件等信息的数据结构（Linux 中为 task_struct）。
23. **命令行解释程序**：接收用户输入的命令行，解析命令和参数，并调用相应程序执行的程序（如 shell）。
24. **指令周期**：CPU 取出并执行一条指令的时间。不同指令的指令周期可能不同。
25. **指令译码器**：对指令操作码进行译码的硬件部件，译码产生的信号送操作控制信号形成部件，由后者产生各部件所需的控制信号。
26. **内部异常**：由 CPU 在执行某条指令时引起的与该指令相关的意外事件，如除数为 0、结果溢出、断点、单步跟踪、寻址错、访问超时、非法操作码、栈溢出、缺页、地址越界（段错误）等；系统调用通过陷阱/自陷指令实现，也属于内部异常。
27. **外部中断**：由外部设备（如硬件中断、时钟中断）引起的中断。
28. **数据通路**：CPU 中数据在各功能部件之间传送所经过的路径，包括 ALU、寄存器、总线等。
29. **执行部件**：CPU 中负责执行指令的部件，包括算术逻辑单元（ALU）等。
30. **功能部件**：CPU 中用于实现特定功能的部件，如乘法器、除法器等。
31. **控制器**：CPU 中负责取指、译码并产生控制信号，协调各部件工作的部件。
32. **时钟信号**：CPU 内部的时钟信号，用于同步各个部件的工作。
33. **指令流水线**：把指令执行过程划分为若干阶段，让多条指令在不同阶段重叠执行的技术；它提高吞吐率，不缩短单条指令的执行时间。

### 二、简答题（14）

**1. 如何将多个 C 程序模块组合生成可执行文件？简述从源程序到可执行文件的转换过程。**

解答：主要包括预处理（Preprocessing）、编译（Compilation）、汇编（Assembly）、链接（Linking）四个阶段。

1. 预处理阶段：对源程序进行预处理，生成预处理后的源程序文件（.i）。
2. 编译阶段：对预处理后的源程序进行编译，生成汇编语言源程序文件（.s）。
3. 汇编阶段：对汇编语言源程序进行汇编，生成可重定位目标文件（.o）。
4. 链接阶段：将多个可重定位目标文件以及所需的库文件进行链接，生成最终的可执行文件。链接器完成符号解析和重定位，将各模块组合成一个完整的可执行文件。

简而言之，从源程序到可执行文件的转换过程是：预处理 .i → 编译 .s → 汇编 .o → 链接生成可执行文件。

**2. 可重定位目标文件和可执行目标文件的主要差别是什么？**

解答：

- 可重定位目标文件是单个模块经编译/汇编生成，代码从 0 开始，地址尚未最终确定，含 .rel.text、.rel.data 等重定位信息，链接后可与其他模块组合。
- 可执行目标文件是多个模块经链接生成，代码/数据位于 ABI 规定的虚拟地址空间，含程序头表，可直接装入执行。

**3. 链接器主要完成哪两方面的工作？**

解答：

- 符号解析：将每个符号的引用与一个确定的符号定义建立关联。
- 重定位：重新确定代码和数据的地址，并更新指令中被引用符号地址。

**4. 可重定位文件的 .text 节、.rodata 节、.data 节和 .bss 节中分别主要包含什么信息？**

解答：

- .text 节：存放程序的代码。
- .rodata 节：存放只读数据，如常量字符串等。
- .data 节：存放已初始化且初值不为 0 的全局和静态变量。
- .bss 节：存放未初始化或初始化为 0 的全局和静态变量；不占文件中的实际空间，运行时分配并置 0。

**5. 可执行目标中有哪两种可装入段？哪些节组合成只读代码段？哪些节组合成可读/写数据段？**

解答：

- 只读代码段：由 ELF 头、程序头表、.init 节、.fini 节、.text 节和 .rodata 节组合而成，访问权限为读/执行。
- 可读/写数据段：由 .data 节和 .bss 节组合而成，访问权限为读/写。

**6. 加载可执行文件时，加载器根据其中哪个表的信息对可装入段进行映射？**

解答：加载器根据程序头表（Program Header Table）中的信息对可装入段进行映射。

**7. 静态链接和动态链接的差别是什么？**

解答：静态链接在链接阶段将静态库中被引用的目标模块合并到可执行文件中，生成可执行文件时就已经确定了符号引用；动态链接是在程序装入或运行时将共享库文件动态装入内存并自动链接，允许多个程序共享同一个库文件，需要动态链接器在装入或运行时解析符号引用。

**8. 在可执行文件中将可装入段映射到虚拟地址空间，以形成每个进程独立的虚拟地址空间，这种做法有什么好处？**

解答：将可装入段映射到虚拟地址空间，使每个进程拥有独立、一致的虚拟地址空间，简化了程序设计、链接和加载；不同进程的相同代码/数据可以共享物理内存，同时通过页表权限实现进程间的存储保护，避免地址冲突。

**9. 简述通过 shell 命令行解释程序进行程序加载的过程。**

解答：大致包括以下几个步骤：

- 用户输入命令行。
- shell 解释命令行，识别要执行的程序。
- shell 调用 fork 创建一个子进程。
- 子进程以 argc、argv、environ 为参数调用 execve；execve 中的加载器根据程序头表初始化进程描述符和虚拟地址空间，并不真正把代码和数据读入主存。
- 加载器把 PC 设定为程序入口点 _start；程序运行发生缺页时，才由缺页处理程序把代码和数据装入主存。

**10. CPU 的基本组成和基本功能各是什么？**

解答：CPU 的基本组成包括算术逻辑单元（ALU）、控制单元、各类寄存器（通用寄存器、PC、IR、标志寄存器等）、指令译码器、时序与控制信号形成部件、总线控制逻辑和中断机构等。其基本功能是周而复始地取出并执行指令，进行算术/逻辑运算和访存，控制程序执行流程，并处理内部异常和外部中断。

**11. 如何控制一条指令执行结束后能够接着另一条指令执行？**

解答：通过程序计数器（PC）实现。顺序执行时，每执行完一条指令，PC 加上当前指令的长度（字节数），指向下一条指令；执行跳转、调用或返回等指令时，PC 被置为目标地址。

**12. 通常一条指令的执行要经过哪些步骤？每条指令的执行步骤都一样吗？**

解答：一条指令的执行通常经过以下六个步骤：①取指令；②指令译码；③计算源操作数地址并取操作数；④执行数据操作；⑤计算目的操作数地址并存结果；⑥计算下条指令地址。每条指令的执行步骤并不完全相同，不同指令在第③～⑤步的操作可能不同。

**13. 流水线方式下，一条指令的执行时间缩短了还是加长了？程序的执行时间缩短了还是加长了？**

解答：在流水线方式下，**单条指令的执行时间并不会缩短**——每条指令仍要依次经历取指、译码、执行、访存、写回各段，还要经过流水寄存器，因此单条指令的执行时间等于“段数 × 每段最长耗时”，往往比串行方式下最长的组合还长。

流水线缩短的是相邻两条指令开始执行的时间间隔，从而提高指令执行的**吞吐率**；因此在忽略数据相关性、控制相关性引起的停顿（冒险）时，**程序总的执行时间会缩短**。设流水线有 M 段、每段耗时 T、共执行 N 条指令，则总时间为 (M − 1 + N) × T，N 越大收益越明显；流水线的速度取决于最慢的那一段（瓶颈段）。

**14. 具有什么特征的指令系统易于实现指令流水线？**

解答：易于实现指令流水线的指令系统通常具有以下特征：①指令长度固定、格式规整，操作码和操作数地址等字段长度固定；②指令类型少、功能简单；③寻址方式简单，只有 Load/Store 指令访存；④采用大量通用寄存器。数据相关性、控制相关性是程序运行时的性质，不属于指令系统本身的特征。

## 第五章 程序的存储访问

### 一、名词解释（60）

1. **随机存取存储器（RAM）**：随机存取存储器，通过对地址译码访问存储单元，每个单元的访问时间与地址无关（不考虑芯片内部缓冲）；属于读/写存储器，断电后信息丢失。主存由 DRAM 组成，cache 由 SRAM 组成。
2. **只读存储器（ROM）**：只读存储器，信息一旦确定通常只读不写，但某些类型（如 EPROM、EEPROM、Flash）可重新写入；属于非易失性存储器，常用于存放启动指令或固件。
3. **易失性存储器**：当电源关闭后，数据会丢失的存储设备。RAM 就是一种易失性存储器。
4. **存储阵列（Bank）**：由存储 0 或 1 的记忆单元构成的存储阵列，是存储器的核心部分；也称为存储体、存储矩阵。
5. **编址单位**：具有相同地址的那些位元构成的一个单位，可以是一个字节（按字节编址）或一个字（按字编址）。
6. **记忆单元（Cell）**：存储设备中最基本的存储单位，用于存储一个二进制位（bit）的信息。
7. **存储周期**：存储器进行连续两次独立的存储器操作（如读或写）之间所需的最小时间间隔。
8. **编址方式**：存储器编址方式包括按字节编址和按字编址等，决定每个地址对应多少位二进制信息；不同编址方式会影响地址空间大小和访问方式。
9. **静态 RAM（SRAM）**：SRAM（Static Random Access Memory）是一种 RAM 类型，它的存储单元使用双稳态电路来存储数据，不需要刷新，因此速度较快但功耗较高。
10. **动态 RAM（DRAM）**：DRAM（Dynamic Random Access Memory）是另一种 RAM 类型，它的存储单元使用电容来存储数据，由于电容会漏电，所以需要定期刷新来保持数据。
11. **闪存（Flash 存储器）**：一种非易失性存储设备，它使用浮栅晶体管来存储数据。闪存常用于 USB 驱动器、SSD 和某些类型的移动设备中。
12. **SDRAM**：SDRAM（Synchronous Dynamic Random Access Memory）是一种同步动态 RAM，其内部命令的发送与接收采用时钟同步方式。它广泛应用于现代计算机系统中。
13. **行地址选通信号（RAS）**：DRAM 中用于锁存行地址的选通信号：行地址先送到芯片的行地址锁存器，RAS 有效时将其锁存。
14. **列地址选通信号（CAS）**：DRAM 中用于锁存列地址的选通信号：行地址锁存后，再送入列地址并由 CAS 锁存，从而选中行/列交叉处的存储单元。
15. **磁盘驱动器**：用于读取和写入磁盘（如硬盘）数据的设备。
16. **寻道时间**：磁盘驱动器将读写头移动到指定磁道所需的时间。
17. **旋转（等待）时间**：磁头到达指定磁道后，指定扇区旋转到磁头下方所需的时间；平均旋转等待时间通常取旋转一周时间的一半。
18. **数据传输率**：单位时间内读/写存储介质的二进制信息量。磁盘有内部传输率（持续传输率）和外部传输率（突发/接口传输率）之分。
19. **固态硬盘（SSD）**：以 NAND 闪存为存储介质的外部存储器，无机械运动、随机访问快、抗振动；但擦写次数有限，需要磨损均衡。
20. **时间局部性**：如果一个信息项被访问，那么在未来不久它很可能再次被访问。
21. **cache 行（槽）**：cache 中存放一个主存块的区域，是 cache 与主存之间的信息交换单位；主存中对应的区域称为主存块。
22. **命中率**：缓存中访问成功的次数与总访问次数的比例。
23. **磁盘控制器**：磁盘存储器中负责控制逻辑、时序、并/串转换和串/并转换的硬件部件，连接主机与磁盘驱动器。
24. **平均存取时间**：磁盘完成一次读/写所需的平均时间，通常 = 平均寻道时间 + 平均旋转等待时间 + 数据传输时间，常近似为前两项之和；不包括排队和控制器解析请求的时间。
25. **空间局部性**：如果程序访问了某个存储单元，那么在不久的将来，其附近的存储单元也很可能被访问。
26. **主存块**：在缓存和主存之间，主存块是主存中可以被作为一个单元整体地传输到缓存中的一组数据。
27. **命中时间**：缓存命中时，从发出数据请求到数据实际可用所需的时间。
28. **缺失损失**：当缓存未命中时，从慢速存储器（如主存）获取数据所需的额外时间和开销。
29. **直接映射（Direct Mapping）**：一种 cache 映射方式。主存被划分为若干块，cache 被划分为若干行；每个主存块只能映射到唯一确定的一行，通常按“cache 行号 = 主存块号 mod cache 行数”确定。地址划分为标记、行号、块内地址三部分。优点是硬件简单、命中时间短；缺点是多个主存块会映射到同一行，冲突较多，命中率较低。
30. **FIFO 算法（First-In-First-Out Algorithm）**：按进入 cache 的先后顺序替换的算法：缓存满时淘汰最早进入的行。实现简单，但不能反映程序访问局部性，缺失率可能较高。
31. **回写法（Write Back）**：写命中时只写 cache、不立即写主存；写缺失时分配 cache 行并装入主存块，然后更新。仅当该行被替换且修改位为 1 时，才把整块写回主存；通常与写分配法组合使用。
32. **物理地址**：主存中各存储单元的真实编号，是可识别、可寻址并实际存在的地址；在采用虚拟存储器的系统中，CPU 发出的是虚拟地址，需由 MMU 转换为物理地址。
33. **未缓存页**：已分配但未调入主存、内容存放在外存的虚拟页；访问时触发缺页异常，由操作系统从外存调入主存。
34. **页表基址寄存器**：用于存放当前进程页表起始地址的寄存器。地址转换时，以页表基址寄存器内容为页表起点，用虚拟页号作为索引找到对应页表项，而不是把整个虚拟地址与基址简单拼接。
35. **快表（TLB，Translation Lookaside Buffer）**：一种缓存机制，用于存储虚拟地址到物理地址的转换表的一部分。当 CPU 需要解析虚拟地址时，首先会查找快表，如果找到对应的转换条目，则可以直接进行地址转换，从而加速地址解析过程。
36. **用户态**：处理器运行用户程序时所处的模式（目态），处于较低特权级，不能执行特权指令，也不能访问内核地址空间。
37. **全相联映射**：一种 cache 映射方式，主存中的任一块可以映射到 cache 中的任意一行，没有固定的对应关系；查找时需要比较所有 cache 行的标记。
38. **LRU 算法（Least Recently Used Algorithm）**：一种常用的缓存置换算法。该算法认为最近最少使用的数据项在未来被访问的可能性最小，因此当缓存满时，会选择最久未使用的数据项进行替换。
39. **组相联映射**：介于直接映射和全相联映射之间的一种缓存映射方式。它将 cache 分成若干组，主存块按“块号 mod 组数”直接映射到唯一确定的某一组（组间直接映射）；而组内的多个行（路）之间是全相联的，一个主存块可以装入该组中的任意一行，组内行满时由替换策略决定替换哪一行。
40. **LRU 位**：LRU 位是记录 cache 组内各行为最近使用情况的计数值，位数与组大小有关（2 路 1 位、4 路 2 位、8 路 3 位）；每次访问后更新，替换时选择计数值最小（最久未使用）的行。
41. **替换策略**：决定了当缓存满时，如何选择数据项进行替换。不同的替换策略会影响缓存的效率和性能。
42. **cache 写策略**：决定了 CPU 对 Cache 中的数据进行修改时，如何更新主存中的数据。常见的写策略包括回写法和通写法。
43. **通写法（Write Through）**：写命中时同时写 cache 和主存，保持两者一致；写缺失时先写主存，可采用写分配法（分配 cache 行并装入主存块）或非写分配法（不装入 cache）。为减少写主存开销，通常加写缓冲。
44. **虚拟地址（逻辑地址）**：用户程序中的地址表示方式，它并不直接对应物理内存中的实际地址。在程序执行过程中，虚拟地址需要通过地址映射或地址重定位转换为物理地址。
45. **虚拟页号**：虚拟地址中的一部分，用于标识虚拟内存中的页面。
46. **页框（页帧）**：物理内存中的一个固定大小的块，用于存储从虚拟内存中加载的数据。
47. **请求分页**：一种内存管理技术，它允许程序在需要时从磁盘或其他辅助存储中加载页面到物理内存中。
48. **有效位（装入位）**：cache 行有效位用于标识该行中的主存块是否有效：装入主存块后置 1，冲刷/替换时清 0。页表项中另有装入位（存在位），用于标识虚拟页是否已在主存，二者不要混淆。
49. **特权指令**：只能由操作系统或具有特权级别的程序执行的指令。这些指令通常用于执行系统级操作，如访问硬件、修改系统状态等。
50. **存储保护**：由 ISA、硬件和操作系统共同实现的机制，防止程序访问或修改不应访问的存储区域；包括访问权限保护（权限位）和存储区域保护（地址越界检查）。
51. **物理页号**：物理地址中的一部分，用于标识物理内存中的页面。
52. **未分配页**：尚未被进程申请使用的虚拟内存页面，它不占用物理内存或磁盘空间。
53. **页故障（Page Fault）**：程序访问的虚拟页不在主存时由 MMU 触发的异常。处理时若主存有空闲页框，直接装入缺失页；没有空闲页框时才按替换算法淘汰一页并写回（若脏位为 1），然后装入缺失页。
54. **页表**：记录虚拟页与主存页框（或外存位置）对应关系的数据结构。每个虚拟页有一个页表项，包含装入位、修改位、使用位、访问权限位、禁止缓存位和存放位置等；MMU 用页表完成虚拟地址到物理地址的转换。
55. **修改位（脏位）**：cache 行的修改位（脏位）标识该行中的主存块是否被写过：装入时清 0，CPU 写 cache 行时置 1；替换该行时若为 1 则写回主存。页表项中也有修改位，用于决定页面替换时是否写回外存。
56. **特权模式**：处理器运行内核程序时所处的模式（管态/内核态），具有较高特权级，可执行特权指令并访问内核地址空间。
57. **地址越界**：程序访问了不该访问的存储区域，如未分配页（空洞）或超越最大段长；属于存储区域保护，不是访问权限不符。
58. **访问权限**：定义了程序或用户对特定内存区域的访问级别，如可读、可写或可执行。
59. **内核态**：处理器运行操作系统内核程序时所处的模式（管态/内核态），具有最高特权级，可执行特权指令并访问所有内存区域。
60. **访问越权**：实际访问操作与页表/段表中设置的访问权限不符（如对只读页写入），发生存储保护错。它与访问越级（用户态访问内核区）、执行特权指令（非法指令/保护错）是不同情况。

### 二、简答题（7）

**1. 计算机内部为何要采用层次结构存储体系？层次结构存储体系如何构成？**

解答：采用层次结构存储体系的原因主要有两点：首先，解决快速的 CPU 和慢速的主存之间的速度差异；其次，解决主存容量不够大的问题。

按速度由快到慢、容量由小到大、价格由贵到便宜、距 CPU 由近到远，依次为寄存器 → cache → 主存 → 硬盘 → 光盘和磁带。cache 由 SRAM 组成，主存由 DRAM 组成；cache-主存之间传送主存块（几十字节），主存-外存之间传送页（几千字节以上）。上层是下层的缓存，依靠程序访问的局部性提高性能。

**2. 为什么采用地址对齐方式能减少访问 DRAM 中数据的时间？**

解答：DRAM 芯片的数据线通常为 64 位，一次最多传送 8 字节；若数据跨越两个 64 位单元，就需要两次访问。按地址对齐存放可使数据落在同一个 64 位单元内，一次访问完成，减少访问次数。

**3. 为什么在 CPU 和主存之间引入 cache 能提高 CPU 的访存效率？**

解答：主要因为程序访问具有时间局部性和空间局部性，把最近使用的指令和数据所在的主存块复制到 cache 后，大多数访问都能在 cache 中命中；cache 访问时间接近 CPU 速度，平均访问时间接近 cache 访问时间，从而提高访存效率。

**4. 为什么直接映射方式不需要考虑替换策略？**

解答：因为直接映射的映射关系是唯一确定的：每个主存块只能装入 cache 中由“块号 mod cache 行数”算出的那一行，行号固定、没有选择余地。因此当该行已被其他块占用时，只能把原来那一行的内容替换掉（覆盖）后再装入，不存在“在若干候选行中选一个”的替换问题，所以无需替换策略。代价是同一行号对应的多个主存块会反复相互替换（冲突），命中率较低。

**5. 为什么要考虑 cache 的写策略问题？**

解答：因为 CPU 对主存的访问与修改过程中，会引发 cache 内容的变化。如果不对 cache 和主存所要修改的内容加以控制，两者的内容会变得不一致。为了确保数据的一致性，需要采用适当的写策略，如回写法或通写法，来决定何时以及如何将 cache 中的数据写回到主存中。

**6. 什么是物理地址？什么是逻辑地址？地址转换由硬件还是软件实现？为什么？**

解答：物理地址是主存中各存储单元的真实编号；逻辑地址是用户程序中的地址（虚拟地址），通常为相对地址形式。地址转换由 MMU 硬件完成，因为每次访存都要转换，硬件速度能满足要求；缺页异常由操作系统软件处理，TLB 缺失按 ISA 可由硬件或软件处理。软件不负责常规地址转换。

**7. 在存储器层次化结构中，“cache-主存”“主存-外存”这两个层次有哪些不同？**

解答：除速度、容量、成本外，关键区别是：cache-主存之间传送主存块（几十字节），由硬件实现，对程序员透明；主存-外存之间传送页（几千字节以上），由 MMU 和操作系统共同实现，缺页时需调页。cache-主存解决主存速度问题，主存-外存解决容量问题。

## 第六章 程序中 I/O 操作的实现

### 一、名词解释（42）

1. **I/O 硬件**：I/O 硬件由机械部分（I/O 设备本身）和电子部分（设备控制器/I/O 适配器）组成，如键盘、鼠标、显示器、磁盘及其控制器。
2. **I/O 软件**：是一组程序和工具，用于管理和控制 I/O 硬件的操作，包括设备驱动程序、中断处理程序、缓冲管理以及相关的系统调用等。
3. **系统调用处理程序**：是操作系统内核中的一部分，负责处理来自用户空间的系统调用请求，实现用户程序与内核之间的交互。
4. **系统调用服务例程**：是系统调用处理程序调用的内核函数，用于实现具体的系统调用功能。
5. **系统级 I/O 函数**：是系统调用封装函数，如 UNIX/Linux 中的 open、read、write、close、creat、lseek、stat 等；C 标准库 stdio（fopen、fread、fwrite 等）是更高层的库函数，不属于系统级 I/O 函数。
6. **虚拟文件系统（VFS）**：VFS 是具体文件系统之上的抽象层，基于 inode 等内存数据结构为上层提供统一的文件操作接口，使 Linux 能同时支持多种文件系统；它不是网络分布式文件系统。
7. **流缓冲区**：用于提高 I/O 操作的效率和性能，通常用于在数据读取或写入时进行暂存，以减少系统调用的次数和内存访问的延迟。
8. **索引节点**：通常用于文件系统中，包含文件的元数据（如文件大小、权限、创建时间等），是文件系统用来定位和访问文件的关键数据结构。
9. **系统打开文件表**：操作系统内核维护的系统级打开文件表，表项包含 inode 指针、当前读/写位置、打开模式、引用计数等信息；文件描述符是进程 fd 表的索引，不在系统表中。
10. **磁盘高速缓存**：是操作系统用于提高磁盘 I/O 性能的一种技术，通过缓存最近访问过的磁盘数据块，减少对磁盘的物理访问次数。
11. **程序直接控制 I/O**：程序直接控制 I/O（查询/轮询方式）由内核驱动程序循环读取设备控制器的状态端口，未就绪时忙等待；就绪后把数据送数据端口并向控制端口发启动命令，CPU 与外设串行工作。
12. **就绪状态**：在多任务操作系统中，通常用于描述一个进程或线程已经准备好执行，等待被调度器分配到 CPU 上运行的状态。
13. **多重中断（中断嵌套）**：在一个中断处理程序执行过程中，又来了优先级更高且未被屏蔽的新中断，CPU 暂停当前中断服务程序，保存断点和现场后转去处理新中断；处理完再逐层返回。
14. **中断嵌套**：与多重中断是同一现象，强调中断处理程序可以被更高优先级的中断打断，形成嵌套。
15. **设备控制器**：是硬件设备与计算机之间的接口电路，负责控制和管理硬件设备的操作，如磁盘控制器、显卡控制器等。
16. **I/O 端口**：设备控制器中的数据缓冲寄存器、状态/控制寄存器等统称为 I/O 端口；CPU 通过 I/O 端口与外设交换数据、状态和控制信息。
17. **状态端口**：设备控制器中用于向 CPU 提供设备状态信息的端口（通常只读）；控制信息一般写控制端口，二者有时合并为一个状态/控制寄存器。
18. **I/O 地址空间**：所有 I/O 端口编号组成的空间。独立编址时它与主存地址空间分离，需专用 I/O 指令访问；统一编址时才与主存地址空间统一。
19. **存储器映射 I/O**：是一种 I/O 技术，通过将 I/O 端口或设备控制器映射到内存地址空间，使得 CPU 可以像访问内存一样访问这些 I/O 设备。
20. **I/O 指令**：是 CPU 执行的指令，用于启动 I/O 操作，如读取或写入数据。
21. **中断响应优先级**：多个中断同时请求时，由查询程序或判优电路决定先响应哪个中断的优先级；通常由硬件排队器/查询程序实现。
22. **中断处理优先级**：中断服务程序在处理过程中能否被新中断打断的优先级，由中断屏蔽字动态设定；响应优先级高的中断不一定能打断正在处理的低优先级中断。
23. **用户空间 I/O 软件**：是运行在操作系统用户空间中的程序，用于处理输入/输出（I/O）操作。这些软件通常通过系统调用来与内核空间 I/O 软件进行交互，从而实现对硬件设备的访问和控制。
24. **内核空间 I/O 软件**：内核空间的 I/O 软件由与设备无关的 I/O 软件、设备驱动程序、中断服务程序三部分组成，负责把用户 I/O 请求转换为对设备控制器的操作并处理中断。
25. **设备驱动程序**：是一种软件，用于控制计算机上的硬件设备（如打印机、键盘、鼠标、音频/视频设备等），以便它们能够与计算机系统协调工作。设备驱动程序通常由设备制造商提供，并与操作系统紧密集成，以便系统可以识别和使用设备。
26. **文件描述符**：文件描述符是一个非负整数（出错返回 -1），是进程 fd 表的索引；fd 表项指向系统打开文件表，后者记录 inode 指针、读写位置、打开模式和引用计数等信息。
27. **目录文件**：目录本身是一种文件，称为目录文件；其数据由若干目录项组成，每个目录项对应目录中的一个文件。目录项主要保存文件名和 inode 号，文件的属性/元数据存放在 inode 中。
28. **高速缓存 RAM**：内核空间主存区中开辟的一块高速缓存，用于存放最近访问过的文件数据，减少磁盘 I/O；也称为磁盘高速缓存，通常采用回写策略。
29. **中断控制 I/O（中断驱动方式）**：CPU 启动第一个 I/O 操作后，把请求进程阻塞并调度其他进程运行；设备每次完成一个 I/O 操作就向 CPU 发中断，CPU 转去执行中断服务程序，处理完后再启动下一个 I/O 操作。
30. **DMA 方式**：DMA（Direct Memory Access）方式是一种允许某些硬件子系统（如磁盘控制器）直接访问主存，而无需通过 CPU 进行数据传输的技术。它提高了数据传输的效率，减少了 CPU 的介入。
31. **控制端口**：是计算机系统中用于发送和接收控制信号的端口。它通常用于与硬件设备通信，以控制设备的操作和行为。
32. **独立编址方式**：是指 I/O 端口地址和内存地址相互独立，使用不同的地址空间进行编址。这种编址方式使得 I/O 端口和内存可以互不干扰地进行访问。
33. **中断服务程序**：是操作系统内核中用于处理特定中断事件的程序。当中断发生时，CPU 会跳转到相应的中断服务程序执行，以处理中断事件。
34. **文件元数据**：是关于文件自身的信息，如文件的创建时间、修改时间、大小、权限等。这些信息通常存储在文件系统的元数据结构中，用于管理和访问文件。
35. **目录项**：目录文件中的一条记录，保存文件名和对应的 inode 号；文件的属性/元数据在 inode 中，目录项本身不保存完整元数据。
36. **I/O 控制方式**：是指计算机系统中用于管理 I/O 操作的方法和技术。常见的 I/O 控制方式包括程序直接控制、中断驱动、DMA 等。
37. **中断屏蔽字**：是一种用于控制中断响应的寄存器或变量。通过设置中断屏蔽字，可以屏蔽或允许特定的中断请求，以实现中断的优先级管理。
38. **DMA 控制器**：是一种硬件设备，用于实现 DMA 方式的数据传输。它负责在内存和设备之间直接传输数据，而无需 CPU 的干预。
39. **数据端口**：是计算机系统中用于传输数据的端口。它通常用于与硬件设备通信，以发送和接收数据。
40. **统一编址方式**：将 I/O 端口地址和内存地址统一编址，使用同一地址空间；可用普通访存指令访问 I/O 端口，但 I/O 端口会占用一部分主存地址空间。
41. **可编程中断控制器**：是一种用于管理中断请求的硬件设备。它允许操作系统对中断进行优先级排序、屏蔽和响应控制，以实现中断的高效处理。
42. **中断请求寄存器**：是用于记录当前待处理的中断请求的寄存器。当中断发生时，相应的中断请求会被记录到中断请求寄存器中，以供 CPU 或中断控制器处理。

### 二、简答题（12）

**1. I/O 子系统的层次结构是怎样的？**

解答：通常从上至下依次为：用户层 I/O 软件、设备独立性软件、设备驱动软件、中断处理软件和硬件（包括机械部件和电子部件）。这种层次结构的设计使得 I/O 操作更加模块化和抽象化，方便了软件的开发和维护。

**2. 系统调用封装函数对应的机器级代码结构是怎样的？**

解答：通常包括若干条传送指令后跟一条陷阱指令。传送指令用于传递系统调用的参数，而陷阱指令（如 int $0x80）则用于使 CPU 陷入内核进行处理。这种结构是系统调用在机器层面的实现方式。

**3. 为什么系统调用的开销很大？**

解答：每次系统调用都有两次上下文切换：先从用户态切换到内核态，处理结束后再返回用户态。进入内核时还要查 IDT、进行特权级检查、从用户栈切换到内核栈并保存用户栈指针、标志寄存器和断点等，返回时再恢复；因此系统调用开销很高。

**4. C 标准 I/O 库函数是在用户态执行还是在内核态执行？**

解答：C 标准 I/O 库函数（如 printf 和 scanf）是在用户态执行的。这些函数提供了用户程序与 I/O 设备之间的接口，但实际的 I/O 操作（如读写数据）是由内核在内核态下完成的。用户态的程序通过系统调用请求内核进行这些操作。

**5. 与 I/O 操作相关的系统调用封装函数是在用户态执行还是内核态执行？**

解答：与 I/O 操作相关的系统调用封装函数（如 open、read、write、creat）本身是**用户空间**的代码，在**用户态**执行。它的机器级代码结构是“若干条传送指令 + 一条陷阱指令”：传送指令把系统调用号和各参数送入指定寄存器，陷阱指令（如 int $0x80）使 CPU 陷入内核；进入内核后，由内核在**内核态**执行相应的系统调用处理程序与系统调用服务例程（如 sys_read），真正完成对设备的 I/O 操作，返回后再回到用户态。

答题保险写法：封装函数（传送指令 + 陷阱指令）在用户态执行；陷阱指令之后由内核执行系统调用服务例程，具体功能由内核软件实现，最终通过设备驱动程序/中断服务程序控制硬件完成。

**6. 什么是程序直接控制 I/O 方式？说明其工作原理。**

解答：程序直接控制 I/O（查询/轮询方式）由内核驱动程序循环读取设备控制器的状态端口；未就绪则继续查询，CPU 处于忙等待；就绪后把数据送数据端口，并向控制端口发启动命令。CPU 与外设串行工作，效率较低。

**7. 为什么在保护现场和恢复现场的过程中，CPU 必须关中断？**

解答：这是因为中断会打断当前的执行流程，如果允许中断发生，可能会干扰正在处理中的操作系统的信息，导致恢复现场时状态不一致，甚至发生错误。关中断可以确保在恢复现场之前，不会有其他中断打断当前的处理过程。

**8. 什么是中断控制 I/O 方式？说明其工作原理。**

解答：中断控制 I/O 方式下，CPU 启动第一个 I/O 操作后，把请求进程阻塞并调度其他进程运行；设备每次完成一个 I/O 操作就向 CPU 发中断，CPU 转去执行中断服务程序，处理完后再启动下一个 I/O 操作。CPU 与外设可并行工作。

**9. DMA 方式能够提高成批数据交换效率的主要原因何在？**

解答：DMA 控制器直接控制内存与设备之间的数据传送，数据不经过 CPU，也不占用 CPU 的指令周期；CPU 只在传输开始时初始化 DMA 控制器、在传输结束时处理中断，因此成批数据交换效率高。

**10. DMA 控制器在什么情况下发出中断请求信号？**

解答：DMA 控制器在数据块传输完毕时发出中断请求信号。这是因为 DMA 控制器负责在内存和设备之间直接传输数据块，当一块数据传输完成后，它需要通知 CPU 以便 CPU 可以进行后续的处理或启动新的数据传输任务。通过发出中断请求信号，DMA 控制器可以确保 CPU 能够及时响应并处理数据传输的完成情况。

**11. I/O 端口的编址方式有哪两种？各有何特点？**

解答：主要有独立编址和统一编址两种。

- 独立编址方式下，I/O 端口单独编号，形成与主存地址空间独立的 I/O 地址空间；CPU 需用专门的 I/O 指令访问，地址码给出 I/O 端口号。
- 统一编址方式下，I/O 端口与主存单元统一编址，使用普通访存指令即可访问 I/O 端口；但 I/O 端口会占用一部分主存地址空间。

**12. 为什么中断控制器把中断类型号放 I/O 总线的数据线上而不是放在地址线上？**

解答：**中断类型号的本质是数据。**地址线的用途与类型号的作用不相符. 数据线本来就是承载信息的通道**简化设计、保证兼容**
