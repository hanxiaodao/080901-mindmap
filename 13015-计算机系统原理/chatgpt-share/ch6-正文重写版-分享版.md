- **用户空间 I/O 软件**：运行在用户空间，提出 I/O 请求，通过系统调用与内核交互。
- **内核空间 I/O 软件**：操作系统中负责 I/O 管理与控制的部分，包括设备无关层、驱动程序、中断服务程序。
- **I/O 硬件**：在内核 I/O 软件控制下，实际完成设备操作与数据交换。
- **运行时系统**：为编程语言提供运行支撑的软件，例如语言库函数的实现；不要把它误归为内核空间 I/O 软件的三层之一。

### 82.2 I/O 子系统三大特性

| 特性 | 含义 | 做题关键词 |
|---|---|---|
| 共享性 | 多个进程可以共享 I/O 子系统及相关资源 | 操作系统统一管理 |
| 复杂性 | 设备的控制方式、状态与细节复杂 | 驱动程序屏蔽差异 |
| 异步性 | 设备速度慢且不同设备速度差异大，常借助异步中断协调 | CPU 与设备可并行工作 |

**真题陷阱：** 2025.04 单选9，问“不是 I/O 子系统特性”的选项，答案为 **同步性**。

### 82.3 设备无关 I/O 软件层

主要组成：

- 文件系统；
- 缓存层；
- 通用块设备 I/O 层。

作用：把多种设备共有的 I/O 功能抽象出来，为上层提供统一接口，尽可能减少上层对具体设备型号的依赖。文件系统内部还可以细分为虚拟文件系统（VFS）、逻辑文件系统等。

**真题陷阱：**

- 2024.10 单选9：设备无关层不含什么？答案：**中断服务程序**。
- 2024.10 填空20：内核空间 I/O 软件的另外两层为**设备驱动程序、中断服务程序**。
- 2026.04 单选10：不属于内核空间 I/O 软件的是**运行时系统**。
- 2025.10 简答26：写出“I/O 软件 + I/O 硬件 → 用户空间 I/O 软件 + 内核空间 I/O 软件 → 内核三层”的完整层次结构。

### 82.4 从用户态到设备的调用路径

`用户程序调用 I/O 函数 → 系统调用封装函数 → 陷阱指令 → system_call → 具体服务例程（如 sys_write）→ 必要时调用驱动 → 设备执行 → 设备完成中断 → 中断服务程序`

这条链是 82、83、86、87、91、93 之间的主线：82 记整体结构，83 记系统调用，86 记文件如何进入内核处理，87 记设备如何传输数据，91/93 记中断如何响应和处理。<Cite refs={["turn321651view1","turn497787view0"]}/>

### 83.1 `write` 的五步执行过程

- IA-32 经典示例：`int $0x80`；也可能使用 `sysenter`，取决于系统环境。
- 系统调用封装函数的机器级代码结构：**传送参数及系统调用号的指令 + 陷阱指令**。
- 在原笔记的 Linux 示例中，系统调用号放在 `EAX` 寄存器中；`system_call` 是统一入口，依据调用号转到具体服务例程 `sys_write`。

### 83.2 两个名词不能混

| 名词 | 作用 | 例子 |
|---|---|---|
| 系统调用处理程序 | 统一入口，接收并分派系统调用 | `system_call` |
| 系统调用服务例程 | 实现具体系统调用功能 | `sys_write` |

### 83.3 为什么系统调用开销大？

2024.04 简答26，答题至少写全以下两点：

1. 系统级 I/O 函数的功能由内核中的系统调用服务例程实现；用户程序每次进行一次系统调用，都需要进入内核执行相应服务。
2. 每次系统调用通常有两次特权级切换：**用户态 → 内核态 → 用户态**。

进一步解释 IA-32 经典机制：陷阱类异常需要进行入口查找、特权级检查、从用户栈切换到内核栈，以及保存相关状态和断点等操作，因而有额外开销。

**减少开销的方法：** 能减少系统调用次数就减少；C 标准 I/O 库利用用户空间流缓冲区，将多次小操作合并为少量较大的系统调用。

### 83.4 用户态 / 内核态判断

- `printf`、`scanf`、`fopen` 等 C 标准 I/O 库函数：通常在用户态执行。
- `open`、`read`、`write` 等系统调用封装函数：封装代码本身位于用户空间。
- 执行到陷阱指令时才转入内核，具体服务例程在内核态执行。

**速记：** `printf → write → 陷阱 → system_call → sys_write → 返回`。不要把“封装函数在用户态执行”和“具体 I/O 功能在内核实现”混为一谈。<Cite refs={["turn497787view0"]}/>

## 84｜用户空间的 I/O 函数 A

<text color="secondary" size="sm">教材第六章习题4；大纲要求领会</text>

### 84.1 两类 I/O 函数

| C 标准 I/O 库函数 | 系统级 I/O 函数 |
|---|---|
| `fopen`、`fread`、`fwrite`、`fclose` | `open`、`read`、`write`、`close` |
| `printf`、`scanf` | `lseek`、`stat`、`fstat` 等 |
| 抽象层次较高，使用 `FILE *` | 接口较底层，使用文件描述符 `fd` |

标准 I/O 库一般建立在系统级 I/O 接口之上，并可使用用户空间流缓冲区减少系统调用次数。

### 84.2 `fopen()` 的实现思路

`检查 mode 合法性 → 在 _iob 数组中寻找空闲 FILE 项 → 按模式调用 creat/open → 填写 fd、cnt、base、flag 等字段 → 返回 FILE 指针`

追加模式 `"a"`：原笔记给出的实现思路为先 `open`，失败再 `creat`，然后用 `lseek` 定位到文件尾。此处是教材所述实现示例，不应当作所有现代 C 库内部实现都必须完全相同的规定。

### 84.3 标准 I/O 库的优缺点

**优点**

- 可移植性好：程序更容易适配不同体系结构与操作系统平台。
- 使用用户空间流缓冲区，减少系统调用次数与 I/O 次数，提高效率。

**缺点（原笔记考试口径）**

- 同步 I/O 调用通常要等待该操作完成后才能继续。
- 标准库不提供所有系统级功能，例如直接查询文件元数据需要 `stat` / `fstat` 等接口。
- 网络编程还需注意缓冲区管理与安全问题；标准 C I/O 库也不直接提供所有文件锁操作。

### 84.4 `getc()` 如何减少系统调用？

- `getc` 通常先从流缓冲区取一个字符，只需要更新 `ptr`（当前位置指针）和 `cnt`（剩余字节数）。
- 当缓冲区耗尽时，才调用类似 `_fillbuf` 的填充函数。
- 原笔记教材例子：`BUFSIZ = 1024`，填充时一次最多读入 1024 字节。
- 若文件长度小于 1024 字节，逐字符复制时：
  - 直接用 `read/write`，每个字符都调用一次，约有 \(2n\) 次系统调用；
  - 用 `getc/putc`，缓冲区足够时，读、写可能各只需一次系统调用。

**核心结论：** 用户空间流缓冲区将“多次小 I/O”合并成“少量大 I/O”。

**易错：** 这里减少系统调用次数靠的是 **用户空间流缓冲区**，不是内核的磁盘高速缓存。系统级函数使用 `fd`，标准库使用 `FILE *`。<Cite refs={["turn497787view0","turn497787view1"]}/>

## 85｜系统级 I/O 函数与文件基本概念 S

<text color="secondary" size="sm">真题：2024.04、2024.10、2025.04；教材第六章习题</text>

### 85.1 “一切皆文件”

Linux/UNIX 将多种 I/O 对象统一成文件接口：

- 键盘：可读取字节序列的输入设备。
- 显示器：可写入字节序列的输出设备。
- 网络套接字：可读、可写的通信对象。
- 磁盘上的普通文件：存储数据的文件。
- 键盘与显示器可对应标准输入、标准输出等终端流。

文件还可按内容形式区分：

- **文本文件**：内容通常以可读字符表示，行常以 `\n` 分隔。
- **二进制文件**：内容按二进制格式组织，如可重定位目标文件、可执行文件。

基本操作：创建 → 打开 → 读 / 写 → 关闭。

### 85.2 文件系统的两项核心功能

2025.04 简答26，按两点作答：

1. 为用户和应用程序提供文件抽象，以及创建、打开、读、写、关闭等操作接口。
2. 将抽象文件标识（文件名、文件描述符等）与具体设备关联，并通过相应驱动程序实现操作。

### 85.3 系统级 I/O 函数：操作与返回值

| 函数 | 功能与必记细节 |
|---|---|
| `creat(name, perms)` | 创建文件；指定访问权限。原笔记例子 `0755` 表示 `rwxr-xr-x`；在传统 `creat` 语义下，已存在文件会被截断 |
| `open(name, flags, perms)` | 打开文件，检查访问权限；成功返回文件描述符 `fd` |
| `read(fd, buf, n)` | 从当前位置读取最多 `n` 字节至 `buf`，返回实际读取字节数 |
| `write(fd, buf, n)` | 请求向当前位置写入 `n` 字节，返回实际写入字节数 |
| `lseek(fd, offset, whence)` | 调整当前文件读写位置 |
| `stat(path)` / `fstat(fd)` | 获取文件元数据；前者按路径，后者按文件描述符 |
| `close(fd)` | 关闭描述符，释放相关资源 |

`open` 常见标志：`O_RDONLY`、`O_WRONLY`、`O_RDWR`、`O_APPEND`、`O_CREAT`、`O_TRUNC`。

**文件描述符默认值：**

- `0`：标准输入 `stdin`
- `1`：标准输出 `stdout`
- `2`：标准错误 `stderr`
- 因此，进程中这三个描述符已经占用时，新 `open` 返回的描述符通常从 `3` 开始。

### 85.4 文件位置、`read()` 与 EOF

设文件长度为 \(m\)，当前文件位置为 \(k\)，请求读取 \(n\) 字节。

- 若剩余字节数足够，实际读取 \(n\) 字节。
- 若剩余字节不足，实际读取 \(m-k\) 字节。
- 读取后文件位置向后移动实际读取的字节数。
- 若到达文件末尾，再调用 `read()` 通常返回 `0`；出错通常返回 `-1`。

**EOF 是文件结束状态，不是文件中实际存储的一个特殊字符。**

`lseek(fd, offset, whence)` 的基准：

- `SEEK_SET`：文件开头；
- `SEEK_CUR`：当前位置；
- `SEEK_END`：文件末尾。

成功返回新的文件位置相对文件开头的偏移量。

**易错：** `lseek` 只调整位置，不负责读取或写入；2024.04 单选10，调整文件读写位置选 `lseek`。

### 85.5 文件缓冲区的三种属性

| 类型 | 何时将缓冲数据送至底层文件描述符 | 原笔记常见场景 |
|---|---|---|
| 全缓冲 | 缓冲区满时 | 普通文件 |
| 行缓冲 | 遇到换行符或缓冲区满时 | 终端 `stdout` |
| 非缓冲 | 不经过普通的流缓冲积累，直接交给底层接口 | `stderr` |

原笔记还列出：`stdin` 的访问模式为 `_READ`；`stdout` 通常行缓冲，`stderr` 通常非缓冲；流缓冲区初始的 `base`、`ptr`、`cnt` 可为 0。

**真题：** 2024.10 单选10，普通文件的缓冲区属性为 **全缓冲**。

| 打开文件描述符表 | `fd` 与系统打开文件表项的对应关系 | 每个进程一张表 |
| 目录项 | 文件名与 inode 号的关联 | 路径查找 |
| VFS 超级块 | 文件系统类型、整体信息等 | 文件系统级信息 |

查找链：

`fd → 进程文件描述符表 → 系统打开文件表项 → inode → 数据寻址 → 文件数据`

### 86.2 例6.2：两次 `open()` 同一个文件

已知 `test.txt` 内容为 `"test"`，程序打开两次，分别得到 `fd1`、`fd2`，每次读取 1 字节。

1. `0/1/2` 已被标准输入、标准输出、标准错误占用。
2. 两次 `open()` 通常分别得到 `fd1=3`、`fd2=4`。
3. 两次打开分别建立独立的系统打开文件表项，初始文件位置均为 0。
4. 两次 `read()` 都从第一个字符开始，因此两次都读到 `'t'`。

原笔记结果：`fd1=3, fd2=4, c=t`。

**核心对比：**

- 两次独立 `open()`：通常有独立文件位置。
- `dup()` 或 `fork()` 继承同一打开文件描述：可能共享系统打开文件表项及文件位置。
- `fd` 是文件描述符表索引，**不是 inode 号**。

### 86.3 VFS、路径名与设备文件

- **VFS（虚拟文件系统）**：为不同文件系统提供统一操作接口，向下对接具体文件系统实现。
- **绝对路径**：以 `/` 开头，从根目录查找。
- **相对路径**：从当前工作目录查找。
- **关闭文件**：释放本进程的描述符表项，系统打开文件表项的引用计数减 1；计数降至 0 时才可以释放相应结构。
- **设备文件**：主设备号用于确定设备类型或驱动，次设备号用于确定具体设备。

### 86.4 缓存层与通用块设备 I/O 层

**磁盘高速缓存（内核缓存）**

- 位于主存中的内核区域，缓存最近访问的文件数据。
- 命中：可直接使用缓存数据。
- 未命中：向下层请求数据。
- 原笔记以回写策略为例：数据修改后可以先留在缓存，之后再写回设备。
- 示例：读取 80B，底层可能读取包含这些数据的整个 4KB 逻辑块到缓存。

**通用块设备 I/O 层**

- 为磁盘、SSD、光盘等提供统一的块设备抽象。
- 统一逻辑块操作，并可调度 I/O 请求，例如合并相邻请求、调整请求顺序。

**两种缓冲不要混：**

| 用户空间流缓冲区 | 内核磁盘高速缓存 |
|---|---|
| 由 `FILE` 等用户空间结构管理 | 位于内核管理的主存区域 |
| 主要减少系统调用次数 | 主要减少实际设备访问并缓存文件数据 |

### 86.5 打开文件与读文件的完整过程

**打开文件：**

`open → 陷阱进入内核 → sys_open → VFS 解析路径 → 查目录项 / inode → 分配 fd 与系统打开文件表项 → 返回 fd`

**读文件（典型路径）：**

`fread → read → sys_read → 按 fd 找文件信息 → 确定逻辑块与设备驱动 → 查缓存 → 未命中时请求设备读取 → 需要时启动 DMA → 进程等待 → DMA 完成中断 → 唤醒进程`

这里把 82 的层次结构、83 的系统调用、85 的文件接口、86 的内核结构与 87 的 DMA 连成了一个完整流程。<Cite refs={["turn497787view2","turn937036view0"]}/>

## 87｜设备驱动程序与三种 I/O 控制方式 S

<text color="secondary" size="sm">真题：2024.04、2024.10、2025.10、2026.04；教材第六章习题6、8、9、10</text>

### 87.1 设备驱动程序是什么？

设备驱动程序是**与设备相关的 I/O 软件**。每个驱动通常负责一种设备或一类紧密相关的设备。

驱动程序需要了解：

- 设备控制器提供哪些可访问寄存器；
- 控制寄存器、状态寄存器各位的含义；
- 如何与设备通信、启动设备及处理状态；
- 如何注册中断服务程序，并与对应的中断号关联。

三种控制方式：**程序直接控制（查询）、中断控制、DMA 控制**。

### 87.2 程序直接控制 I/O（查询 / 轮询）

**基本思想：** 通过查询程序，直接控制主机与外设的数据交换。

以打印机为例：

`读状态端口 → 未就绪则重复查询 → 就绪后把字符送入数据端口 → 向控制端口发启动命令 → 重复直到全部数据完成`

特点：

- 优点：简单、容易实现、控制电路简单。
- 缺点：设备未就绪时 CPU 仍不断查询，产生**忙等待**。
- 查询期间 CPU 与设备的工作基本串行，用户进程在这种基本模型下不因等待设备而阻塞。
- 适用：简单、低速或数据传输要求不高的场景。

**真题：**

- 2024.04 填空20：直接通过什么控制主机与外设的数据交换？答案：**查询程序、数据**。
- 2026.04 简答25：简述程序直接控制 I/O 方式的基本思想，按“查询设备状态、就绪后交换数据、重复直至完成”作答。

### 87.3 中断控制 I/O

**简答题标准流程：**

<box border radius="lg" padding={3} gap={2} align="center">
  <box background="#E0ECFF" theme="light" radius="md" padding={3} width="100%" align="center">
    ① 启动外设，先进行**第一个数据**的 I/O 操作
  </box>
  <icon name="arrow-down" color="secondary" />
  <box background="#DDF5E5" theme="light" radius="md" padding={3} width="100%" align="center">
    ② 阻塞请求 I/O 的用户进程，调度其他进程执行
  </box>
  <icon name="arrow-down" color="secondary" />
  <box background="surface-secondary" radius="md" padding={3} width="100%" align="center">
    ③ 外设在控制器控制下工作，CPU 可并行执行其他任务
  </box>
  <icon name="arrow-down" color="secondary" />
  <box background="#FFF0D9" theme="light" radius="md" padding={3} width="100%" align="center">
    ④ 外设完成后发中断请求，CPU 转入中断服务程序
  </box>
  <icon name="arrow-down" color="secondary" />
  <box background="#F3E8FF" theme="light" radius="md" padding={3} width="100%" align="center">
    ⑤ 服务程序处理状态，并启动**后续数据**的 I/O 操作
  </box>
  <icon name="arrow-down" color="secondary" />
  <box background="surface-secondary" radius="md" padding={3} width="100%" align="center">
    ⑥ 数据全部完成后，解除进程阻塞，将其放入就绪队列
  </box>
</box>

中断服务程序的典型处理：

1. 通知控制器已收到中断，清除中断请求。
2. 判断所有数据是否完成。
3. 若未完成，送入下一个数据、启动设备并更新计数。
4. 若全部完成，解除用户进程阻塞并放入就绪队列。
5. 返回被打断的执行流程。

**进程状态易错：** 等待 I/O 完成的是阻塞态；解除阻塞后先进入就绪态，并非必然立即运行。

**适用：** 需要响应，但设备速度不特别高的场景。

### 87.4 DMA（直接存储器访问）

**核心：数据在外设与主存之间直接传输，不需要 CPU 逐字搬运。**

DMA 控制器常见寄存器：

- 主存地址寄存器；
- 设备地址寄存器；
- 字计数器；
- 控制寄存器。

**流程：**

`CPU 初始化 DMA（数据量、设备地址、主存首地址、方向） → 启动 DMA → CPU 可转去执行其他进程 → DMA 控制器在设备与主存间传输数据 → 每传一个数据更新地址与计数器 → 整个数据块传完后发完成中断 → 服务程序处理完成状态、解除进程阻塞`

DMA 不需要 CPU 执行指令逐字搬运，但仍然占用总线 / 存储器带宽，可能与 CPU 访存竞争资源。

**适用：** 高速、大批量数据传输，例如磁盘数据传输。

### 87.5 三种方式横向对比

| 比较点 | 程序查询 | 中断控制 | DMA |
|---|---|---|---|
| 谁控制传输 | CPU 轮询 | CPU 响应中断并处理数据 | DMA 控制器控制数据块传输 |
| 数据搬运 | 经过 CPU | 通常由 CPU 处理 | 设备 ↔ 主存，不经 CPU 逐字搬运 |
| CPU 等待特点 | 忙等待 | 设备工作期间可执行其他进程 | 传输期间可执行其他进程 |
| 完成通知 | 查询状态 | 中断 | 数据块完成后中断 |
| 适用场景 | 简单、低速 | 中等速度、需要响应 | 高速、大批量 |

**真题与陷阱：**

- 2025.10 单选10：主要由硬件控制外设与主存交换数据 → **DMA**。
- 记忆链：查询经过 CPU、中断方式通常经过 CPU、DMA 不需要 CPU 逐字搬运。
- DMA 是**整块数据传输完成后**再发完成中断，不是每传一个数据就中断一次。<Cite refs={["turn937036view0","turn937036view1"]}/>

### 88.3 三种总线与传统芯片组

1. **处理器总线**：例如教材所述前端总线 FSB、QPI。
2. **存储器总线**：例如 DDR 系列存储器总线。
3. **I/O 总线**：例如 PCIe。

## 90｜I/O 端口及其编址 S

<text color="secondary" size="sm">真题：2025.04 填空20；教材第六章习题10、简答11</text>

### 90.1 两种编址方式

<box gap={2}>
  <box border radius="lg" padding={3} gap={2}>
    <title size="md">① 统一编址（存储器映射 I/O）</title>
    - I/O 端口与主存共用同一地址空间。
    - 地址空间中划出一部分地址分配给 I/O 端口。
    - 用普通访存指令访问端口，无需专用 I/O 指令。
    - 因为访问使用同一组指令，其保护机制可利用虚拟存储管理机制。
    - 缺点：占用一部分主存地址空间，可供主存使用的地址范围减少。
    - 原笔记示例：RISC 架构常采用此方式；MIPS32 的 I/O 映射区域可采用非缓存映射以保证 I/O 访问一致性。
  </box>
  <box border radius="lg" padding={3} gap={2}>
    <title size="md">② 独立编址（I/O 映射）</title>
    - I/O 端口有独立于主存的 I/O 地址空间。
    - 必须通过专用 I/O 指令区分 I/O 访问与普通访存，例如 x86 的 `in`、`out`、`ins`、`outs`。
    - 优点：不占用主存地址空间；端口数量较少时地址译码可以更简单。
    - 缺点：专用 I/O 指令通常只提供较简单的传输操作，编程灵活性相对较低。
    - 原笔记的 x86 示例：I/O 地址空间包含 65,536 个 8 位端口；两个连续 8 位端口可组合成 16 位端口。
  </box>
</box>

### 90.2 I/O 端口术语

- **数据端口**：设备控制器中的数据缓冲寄存器。
- **状态端口**：状态寄存器。
- **控制端口**：控制 / 命令寄存器。
- **I/O 地址空间**：所有 I/O 端口编号所组成的空间。

**真题：** 2025.04 填空20：

> 统一编址方式下，I/O 访问和主存访问共用同一组 **指令**，因此其保护机制可由 **虚拟存储** 管理机制实现。

**对照口诀：**

- 统一编址：共用地址空间、共用访存指令、可利用虚拟存储保护、占用主存地址空间。
- 独立编址：独立 I/O 地址空间、专用 `in/out` 指令、不占用主存地址空间。

**注意：** I/O 端口属于设备控制器一侧，不是 CPU 内部寄存器。<Cite refs={["turn727040view0"]}/>

## 91｜中断系统 S

<text color="secondary" size="sm">真题：2025.10 填空20；教材第六章习题12</text>

### 91.1 中断系统的基本功能

1. **记录中断请求**：通常通过中断请求寄存器记录各中断源的请求。
2. **自动响应中断**：CPU 处于允许中断状态时，在适当的指令边界检测请求。
3. **中断判优**：多个请求同时出现时，选择优先级最高且未被屏蔽的请求。
4. **保护断点和现场**：使被打断程序能够正确恢复执行。
5. **支持中断嵌套**：通过中断屏蔽机制决定哪些新中断可以打断当前服务程序。

### 91.2 断点与现场

| 名词 | 含义 | 保存要点 |
|---|---|---|
| 断点 | 被打断程序将要继续执行的下一条指令地址 | 由 CPU 的中断响应机制保存 |
| 现场 | 被打断程序的通用寄存器等运行状态 | 通常由中断服务程序保存 |

**易错：** 断点是地址，现场是寄存器等状态信息，不能互换。

### 91.3 两种中断优先级

| 优先级 | 解决什么问题 | 由什么决定 |
|---|---|---|
| 中断响应优先级 | 多个中断同时请求时，先响应谁 | 中断判优电路或查询程序 |
| 中断处理优先级 | 当前服务程序执行时，哪些中断可以打断它 | 中断屏蔽字及嵌套控制 |

记忆：**响应优先级管“先响应谁”，处理优先级管“谁能打断谁”。**

### 91.4 中断屏蔽字与 PIC

- 中断屏蔽字的每一位对应一个中断源，用于允许或屏蔽该中断；软件可根据系统需要修改。
- 原笔记采用的教材口径：屏蔽位 `1 = 允许`、`0 = 不允许（屏蔽）`。具体硬件也可能采用相反的位定义，答题以题目 / 教材约定为准。
- 可编程中断控制器 PIC 接收设备控制器的 IRQ 请求，记录请求、进行判优，并通过中断请求信号通知 CPU。
- 判优后得到中断号（中断类型号）；操作系统依据中断号调出相应的中断服务程序。
- **中断类型号放在数据线上而不是地址线上**：它表示中断原因 / 来源，是要传给 CPU 的信息；地址线用于定位存储单元或端口。

**真题：** 2025.10 填空20，填写“中断响应优先级”和“中断处理优先级”。

**边界条件：** CPU 通常在允许中断的状态下，并在适当的指令边界响应中断；处理中断时可能暂时关闭中断，以避免现场保护 / 恢复过程被打断。<Cite refs={["turn727040view0","turn727040view1"]}/>

## 92｜总线性能计算 S

<text color="secondary" size="sm">真题：2025.04 计算28；教材第六章习题7、8、9</text>

### 92.1 通用公式与单位

\[
\boxed{\text{带宽}=\text{每秒传输次数}\times\text{每次有效传输的字节数}}
\]

如果每次传输的有效数据宽度为 \(w\) bit：

\[
\boxed{\text{带宽}=\text{传输率}\times\frac{w}{8}}
\]

多通道总带宽：

\[
\boxed{\text{总带宽}=\text{单通道带宽}\times\text{通道数}}
\]

先区分三个概念：

- **时钟频率**：每秒有多少时钟周期。
- **数据传输率**：每秒实际进行多少次数据传输，常用 MT/s、GT/s。
- **带宽**：每秒传输多少数据量，常用 MB/s、GB/s。

注意：若频率用 MHz、数据宽度用 Byte，计算得到的数值单位通常为 MB/s；若频率用 GHz，则对应 GB/s。计算前要统一单位。

### 92.2 FSB 前端总线

原笔记采用四倍并发（Quad Pumped）技术：每个总线时钟周期传输 4 次。

\[
\text{传输率}=\text{时钟频率}\times4
\]

\[
\text{带宽}=\text{传输率}\times\frac{64}{8}
\]

**2025.04 计算28（1）：**

已知时钟频率 333 MHz，采用 4 倍并发，数据宽度 64 bit。

第一步：算传输率。

\[
333\times4=1332\text{ MT/s}
\]

教材习惯写约 1333 MT/s。

第二步：64 bit 换成 8 Byte。

\[
1332\times8=10656\text{ MB/s}
\]

所以带宽约为 **10.656 GB/s**；若按 1333 计算，则为 10.664 GB/s。

**易错：** 先乘 4 算传输率，再将 64 bit 除以 8 换算成 Byte。

### 92.3 QPI 总线

原笔记的 QPI 示例有三个关键条件：

- 每个时钟周期传输 2 次数据；
- 每次传输的 20 bit 中，只有 16 bit 是有效数据，其余 4 bit 用于 CRC；
- 双向传输，可同时发送和接收，因此总带宽计算乘 2。

\[
\text{传输率}=\text{时钟频率}\times2
\]

\[
\boxed{\text{总带宽}=\text{传输率}\times\frac{16}{8}\times2}
\]

**2025.04 计算28（2）：** 时钟频率 2.4 GHz。

第一步：

\[
2.4\times2=4.8\text{ GT/s}
\]

第二步：有效数据 16 bit = 2 Byte，再考虑双向传输。

\[
4.8\times2\times2=19.2\text{ GB/s}
\]

答案：传输率为 4.8 GT/s，总带宽为 **19.2 GB/s**。

**易错：** 有效数据是 16 bit，不是 20 bit；别漏掉双向系数 2。

### 92.4 存储器总线：DDR

DDR 在一个时钟周期的上升沿和下降沿各传输一次数据。

\[
\text{传输率}=\text{时钟频率}\times2
\]

\[
\text{单通道带宽}=\text{传输率}\times\frac{\text{数据宽度（bit）}}{8}
\]

\[
\text{总带宽}=\text{单通道带宽}\times\text{通道数}
\]

**例：DDR3-1333，64 bit，3 通道**

\[
1333\times\frac{64}{8}=10664\text{ MB/s}
\]

\[
10664\times3=31992\text{ MB/s}
\]

即约 **31.992 GB/s**。

DDR3-1066 的单通道带宽为：

\[
1066\times8=8528\text{ MB/s}
\]

3 通道总带宽约为 **25.584 GB/s**。

**易错：** 如果题目直接给出 DDR3-1333 的 1333 MT/s，就已经包含双边沿传输效果，不能再乘一次 2。

### 92.5 PCIe 总线

PCIe 是串行总线，按通道数扩展，并需要考虑编码效率。

- PCIe 1.0 / 2.0：采用 8b/10b 编码，有效率为 \(8/10\)。
- PCIe 3.0 / 4.0 / 5.0：采用 128b/130b 编码，有效率为 \(128/130\)。
- PCIe 链路通常可以双向同时传输。
- `PCIe ×n` 表示有 \(n\) 条通路（lane）。

原笔记采用的总带宽计算模板：

\[
\boxed{\text{带宽}=\text{速率}\times2\times\text{编码效率}\times\frac18}
\]

最后再乘通道数 \(n\)。

**例：PCIe 1.0，单通路速率 2.5 Gb/s**

\[
2.5\times2\times\frac8{10}\times\frac18
=0.5\text{ GB/s}
\]

因此：

- ×8：\(0.5\times8=4\text{ GB/s}\)
- ×16：\(0.5\times16=8\text{ GB/s}\)
- ×32：\(0.5\times32=16\text{ GB/s}\)

**例：PCIe 3.0，单通路 8 Gb/s**

\[
8\times2\times\frac{128}{130}\times\frac18
\approx1.969\text{ GB/s}
\]

这是按原笔记的编码效率与双向带宽口径计算的结果。

### 92.6 四类总线计算速记

| 总线 | 关键因素 | 最容易错在哪里 |
|---|---|---|
| FSB | 时钟频率 × 4，64 bit ÷ 8 | 忘记四倍并发 |
| QPI | 频率 × 2 次传输 × 2 Byte 有效数据 × 双向 2 | 使用 20 bit 而非有效 16 bit |
| DDR | 给定 MT/s × 数据宽度 ÷ 8 × 通道数 | 把 DDR 双边沿重复乘 2 |
| PCIe | 速率 × 双向 × 编码效率 ÷ 8 × 通道数 | 忘记编码效率或 bit → Byte 换算 |

以上计算公式及例题按原笔记 92.2—92.7 的口径整理。<Cite refs={["turn727040view1","turn727040view2"]}/>

## 93｜中断服务程序与多重中断 S

<text color="secondary" size="sm">真题：2026.04 填空20；教材第六章习题7</text>

### 93.1 中断响应与中断处理

中断过程可以分成两个大阶段：

- **中断响应阶段（硬件）**：关中断、保存断点、转入预先设定的中断服务程序。
- **中断处理阶段（软件）**：执行中断服务程序，完成设备相关处理。

不同教材可能对中断响应内部步骤的描述顺序略有不同；按题目教材口径作答时，把关键步骤写全。

### 93.2 中断服务程序的三个阶段

<box border radius="lg" padding={3} gap={2}>
  <box background="#E0ECFF" theme="light" radius="md" padding={3} gap={1}>
    **① 准备阶段**

    - 把需要保留的通用寄存器现场保存到栈上。
    - 若要允许新中断嵌套，先保存旧中断屏蔽字，再设置新屏蔽字，必要时开放中断。
    - 不需要响应新中断时，可以省略相应的嵌套设置步骤。
  </box>
  <box background="#DDF5E5" theme="light" radius="md" padding={3} gap={1}>
    **② 处理阶段**

    - 从中断控制器取得中断号。
    - 根据中断号查找相应服务程序。
    - 通知设备中断已收到、清除中断请求。
    - 执行具体设备处理，例如传输下一个字符或判断是否全部完成。
  </box>
  <box background="#F3E8FF" theme="light" radius="md" padding={3} gap={1}>
    **③ 恢复阶段**

    - 关闭中断，避免恢复现场过程中再被打断。
    - 恢复寄存器现场与旧屏蔽字。
    - 执行中断返回指令，返回被打断的程序。
  </box>
</box>

**2026.04 填空20：** 中断服务程序包含准备、处理、恢复三个阶段。

**易错：** 必须写“恢复阶段”，不能把它笼统写成“结束阶段”。

### 93.3 多重中断（中断嵌套）

定义：正在执行中断服务程序时，如果有允许响应且优先级更高的新中断到来，CPU 暂停当前服务程序，转去处理新中断，这就是多重中断。

**嵌套过程：**

`用户进程 → 1 号中断 → 2 号中断打断 1 号 → 3 号中断打断 2 号 → 3 号返回 2 号 → 2 号返回 1 号 → 1 号返回用户进程`

- 中断嵌套依靠栈保存断点及程序状态。
- 返回时遵循后进先出（LIFO），先返回最近一次被打断的位置。
- 是否允许新中断嵌套，取决于当前服务程序设置的屏蔽字。

### 93.4 为什么保护和恢复现场时要关中断？

如果在现场保存或恢复过程中被另一个中断打断，寄存器或屏蔽字可能处于不完整状态，造成状态不一致。

因此，教材流程的核心是：

`中断响应时关中断 → 准备阶段按需开放中断 → 恢复阶段先关中断 → 恢复现场 → 中断返回`

**断点与现场再区分一次：** 硬件中断响应机制负责保存断点及部分状态；通用寄存器等现场通常由中断服务程序保存与恢复。<Cite refs={["turn727040view2"]}/>

## 94｜中断 / DMA 开销计算 S

<text color="secondary" size="sm">真题：2026.04 分析设计29；教材第六章例6.3、例6.4、习题13—15</text>

这是本章最需要保留计算步骤的考点：既有中断占用率，也有 DMA 传输对总线与 CPU 执行速度的影响。

### 94.1 三个核心公式

\[
\boxed{t=\frac{\text{缓冲器容量（B）}}{\text{数据传输率（B/s）}}}
\]

\(t\)：一次缓冲器数据传输所对应的时间间隔。

\[
\boxed{T=\frac{\text{单次中断处理周期数}}{\text{CPU 主频}}}
\]

\(T\)：单次中断响应与处理的 CPU 时间。

\[
\boxed{\text{传送期间 CPU 占用率}=\frac{T}{t}}
\]

如果设备只在总时间的一部分进行传送：

\[
\boxed{\text{平均占用率}=\frac{T}{t}\times\text{设备工作时间占比}}
\]

**判断能否使用中断方式：** 比较 \(T\) 和 \(t\)。若单次开销远小于中断间隔，通常可行；若 \(T\ge t\)，CPU 可能几乎全部耗在 I/O 处理中，无法及时处理后续数据。

### 94.2 例6.3：硬盘采用中断方式

原笔记条件：

- CPU 主频 3 GHz；
- 硬盘传输率 128 MB/s；
- 控制器数据缓存 512 B；
- 每次中断处理 512 B；
- CPU 每读取一个 4 B 的字，需要 24 个时钟周期；
- 系统调用开销 3 μs，阻塞 / 调度 1.5 μs，中断响应并进入服务程序 0.5 μs，唤醒返回 3 μs。

**第一步：传输 512 B 需要多久？**

\[
t=\frac{512}{128\text{ MB/s}}=4\ \mu s
\]

**第二步：CPU 读取 512 B 的数据开销。**

512 B 中有 \(512/4=128\) 个字，每个字 24 个周期：

\[
128\times24=3072\text{ 周期}
\]

\[
T_{\text{读数据}}=\frac{3072}{3\text{ GHz}}=1.024\ \mu s
\]

原笔记按约 1 μs 计算。

**第三步：传输 4 KB，需要 8 次中断。**

每轮时间：

\[
3+(4+0.5+1)\times8+3=50\ \mu s
\]

这里按原笔记将读数据开销约为 1 μs；系统调用与唤醒返回各计 3 μs。

**第四步：计算硬盘实际工作占比。**

\[
\frac{4\times8}{50}=64\%
\]

所以实际数据传输率：

\[
128\times64\%=81.92\text{ MB/s}
\]

进程 B 的时间占比：

\[
\frac{(4-1.5)\times8}{50}=40\%
\]

**结论：** 中断服务开销在小块、高速传输场景下占比很高，会拉低实际传输效率。

### 94.3 例6.4：改用 DMA

原笔记将单次 DMA 传输块大小分别设为 4 KB 和 32 KB。

| 传输块大小 | 数据传输时间 | 每轮总时间 | 硬盘工作占比 | 实际传输率 | 进程 B 占比 |
|---|---:|---:|---:|---:|---:|
| 4 KB | 32 μs | 38.5 μs | 83.12% | 106.39 MB/s | 79.22% |
| 32 KB | 256 μs | 262.5 μs | 97.52% | 124.83 MB/s | 96.95% |

公式：

\[
t_{\text{传输}}=\frac{\text{数据块大小}}{128\text{ MB/s}}
\]

\[
\text{实际传输率}=128\text{ MB/s}\times
\frac{t_{\text{传输}}}{t_{\text{每轮}}}
\]

**结论：** 数据块越大，启动、结束中断等固定开销分摊到每个字节上的比例越低。DMA 更适合高速、大批量 I/O。

### 94.4 教材题13：打印机能否采用中断方式？

条件：6 页/min，每页 50 行，每行 80 字符。

每分钟字符数：

\[
6\times50\times80=24000
\]

每秒字符数：

\[
\frac{24000}{60}=400\text{ 字符/s}
\]

每次中断间隔：

\[
t=\frac1{400}\text{ s}=2.5\text{ ms}
\]

若中断处理为 1000 个周期、CPU 主频 500 MHz：

\[
T=\frac{1000}{500\text{ MHz}}=2\ \mu s
\]

因为 \(2\ \mu s\ll2.5\text{ ms}\)，所以可以采用中断方式。

CPU 占用率约为：

\[
\frac{2\ \mu s}{2500\ \mu s}\times100\%=0.08\%
\]

### 94.5 教材题14：16 位缓存器与 16B 缓存器不能混淆

**第一步：位换字节。**

\[
16\text{ bit}=2\text{ B}
\]

若数据率为 20 KB/s：

\[
t=\frac{2\text{ B}}{20\text{ KB/s}}=100\ \mu s
\]

500 MHz CPU、500 个周期的中断开销：

\[
T=\frac{500}{500\text{ MHz}}=1\ \mu s
\]

占用率：

\[
\frac1{100}\times100\%=1\%
\]

可采用中断方式。

若数据率提高到 2 MB/s：

\[
t=\frac{2\text{ B}}{2\text{ MB/s}}=1\ \mu s
\]

此时 \(T=t=1\ \mu s\)，占用率达到 100%，不适合采用这种中断方式。

### 94.6 2026.04 分析设计29：主机占用率

题目条件：

- CPU 主频 500 MHz；
- 磁盘控制器数据缓存 16 B；
- 磁盘传输率 4 MB/s；
- 每次中断开销 500 个时钟周期；
- 磁盘仅有 5% 的时间在传送数据。

**第一步：算中断间隔。**

\[
t=\frac{16\text{ B}}{4\text{ MB/s}}=4\ \mu s
\]

**第二步：算每次中断开销。**

\[
T=\frac{500}{500\text{ MHz}}=1\ \mu s
\]

**第三步：算传送期间占用率。**

\[
\frac{1}{4}\times100\%=25\%
\]

**第四步：乘设备工作时间占比。**

\[
25\%\times5\%=\boxed{1.25\%}
\]

答案：主机平均用于硬盘 I/O 的时间占比为 **1.25%**。

### 94.7 教材题15：DMA 对指令执行速度的影响

条件：磁盘数据传输率为 1 MB/s，DMA 每次传输 16 bit（2 B），每次传输占用一个总线周期，周期为 250 ns。

每秒 DMA 传输次数：

\[
\frac{1\text{ MB/s}}{2\text{ B}}=0.5\text{ M 次/s}
\]

总线每秒被 DMA 占用的时间：

\[
0.5\text{ M}\times250\text{ ns}=0.125\text{ s}
\]

所以总线占用率：

\[
\frac{0.125}{1}\times100\%=12.5\%
\]

在题目假定 CPU 访存与 DMA 访存竞争总线、且损失按占用比例计算时，指令执行速度降低 **12.5%**。

### 94.8 全考点易错清单

- `1 MB/s = 1 B/μs`（按十进制 MB 口径）。
- `16 位缓存器 = 2 B`；`16 B 缓存器 = 16 B`。
- 中断间隔先算 \(t=B/R\)，单次处理时间再算 \(T=C/f\)。
- **传送期间占用率**与**平均占用率**相差一个设备工作时间占比。
- 2026.04 题目要额外乘 5%，结果为 1.25%。
- 判断中断方式是否可行，比较的是时间间隔 \(t\) 与处理开销 \(T\)，不是简单比较数据量。
- DMA 不需要 CPU 逐字搬运，但仍会占用总线资源。
